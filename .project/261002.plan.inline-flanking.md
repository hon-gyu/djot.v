# Plan: emphasis flanking and nonempty content over all inputs (M2, M3)

## Goal

Raise two rows of `syntax-reference-coverage.md` from T~ to T:

| Row | Reference ("Emphasis/strong") |
| --- | --- |
| M2 | "can open emphasis only if it is not directly followed by whitespace.  It can close ... only if it is not directly preceded by whitespace" |
| M3 | closes "only if there are some characters besides the delimiter character between the opener and the closer" |

Both are T~ today through `para_inlines_valid`, whose alphabet leaves out
verbatim, autolinks, attributes, math, spans, images, footnote
references, smart quotes and backslashes.  Triage item 9 asks for the
rules over all inputs.

The rules are about bytes: what follows an opener and what precedes a
closer in the source.  The semantic tree cannot say that, since an
`Emph` node does not record which `_` opened it.  The located parse
does: every delimiter node gets a span from its opener's first byte to
its closer's last.  So the statement is on the located parse, and the
work is to show that the span it records is where the tokens are.

## Statement

For a paragraph's lines `l` (any bytes), every node built for a
delimiter row `k` anywhere in `para_inlines_at off l` at `located_pos`
has a span `[a, b)` such that, reading `l` as the content (lines joined
by a break):

1. the text at `a` is the row's token, or `{` and the token for a marked
   opener;
2. the text ending at `b` is the token, or the token and `}` for a marked
   closer;
3. **M2**: for a bare opener, the byte after the token exists, is not a
   break, and is not whitespace; for a bare closer, the byte before it
   exists, is not a break, and is not whitespace;
4. **M3**: the opener and the closer do not touch: at least one byte lies
   between them.

At `semantic_pos` the nodes are the same up to erasure
(`para_inlines_at_erase`), so the statement is about the parser every
other theorem is about, not a second one.

Then lift to documents: every inline container the block layer builds
(paragraph, heading, caption, cell, ...) is `para_inlines_at` or
`parse_inline_line_located` of strings that are the right slices of the
source lines, so the four clauses hold on the source buffer.

## Approach

### Stage 1: the cursor is faithful

State what the located driver gives the scanner: when `iscan_str_located`
steps byte `c` with `cursor_in k rem origin`, the source byte at
`Spot k rem` is `c`.  Define `src_at l p` (the byte at a spot, or a
break between lines) and `src_slice l a b`.  This is a fact about the
driver alone and should be short.  `lines_stop` and the stripped last
line need care: the scan sees the stripped text, the spots count from
the unstripped one.

### Stage 2: openers are recorded where they are

An invariant on scanner states: every delimiter frame's `fr_open` is a
span whose slice is the frame's token (clause 1), and for a bare frame
the byte after it is not whitespace (M2's opener half).  `dtoken_span`
computes the start with `spot_before` from the cursor; that the token is
the bytes just read follows from stage 1 and the fact that a delimiter
token holds no line break.

The invariant mentions only delimiter frames, so most scanner states
(verbatim, attributes, autolinks, destinations) preserve it because they
do not touch the frame stack, or touch it only by `oflatten`-style
moves that keep `fr_open`.  The cases to prove are the pushes
(`opush`, `opush_at` with `closemark`) and the frame rewrites
(`oset_cur`, `oemit`, `omark`, the bracket dispositions).

### Stage 3: nodes are closed where they are

A second invariant: every delimiter node in the state (in `os_out`, in
any frame's items, in any `oitem`) satisfies clauses 1 to 4.  A node is
built only by `oclose` (check this first: grep every `dnode` and every
`imk` of a delimiter payload, including `oresolve` and the finish), from
a frame meeting stage 2 and a `stop` the caller supplies after the
closer.  The closer half of M2 is `nonspace_at prev` in the closer test;
M3 is `nonempty content`, which needs a lemma that a nonempty `oitems`
covers at least one byte between `fr_open`'s end and the closer.

Every other operation moves nodes without changing their `pos`, or
changes only roles (`add_inline_role`) or attributes (`add_attr`).
Prove that once, as "the delimiter nodes of the result are among those
of the input" for each operation, so the per-state proof does not
reopen node shapes.

`ifinish` and the break between lines (`ibreak_at`) close the paragraph;
both only flatten frames to text, which builds no delimiter node.

### Stage 4: documents

The block layer calls `para_inlines_at` with `(line index, stored text)`
pairs and `parse_inline_line_located` for cells.  Prove that every such
stored text is a suffix of its source line (F2, so far only probed),
and that a cell's `rem` locates its trimmed text.  Then the inline
statement transfers to the source buffer, with "the byte before" a
closer at a stored line's start read as the break, not as the
container prefix before it in the raw source (see Pitfalls).

Stage 4 is where the risk is unknown: F2 has no theorem, and the step
functions are many.  If it is too large, record M2 and M3 as T at the
inline level ("over every paragraph's content") with stage 4 as the gap,
and keep the coverage notes honest about it.

## Pitfalls

- **"Before" and "after" are in the content, not the raw source.**  In
  `> *a` / `>*`, the second `*` starts its stored line: the raw byte
  before it is `>`, not whitespace, while the scanner sees a break.  The
  reference means the inline content, so the statement is on the content
  and the lift has to say so.
- **M3's wording.**  "some characters besides the delimiter character":
  `{___}` is emphasis around `_` in the model, the parser and djot.js
  (inline-precedence plan, stage 3), so the literal reading is not what
  any implementation does.  State M3 as "at least one byte between" and
  note the wording in the coverage row.  Confirm `___` and `{___}` again
  with djot.js before fixing clause 4.
- **Empty delimiter nodes exist.**  A scope holding only an attribute
  spec with nothing to attach to closes onto nothing (`oclose_go`
  comment), so `_{.a}_` has an `Emph` with no children.  Clause 4 holds
  on bytes (`{.a}` is between) and would fail on children.  This is the
  reason to state M3 on spans and not on the tree.
- **Which rows.**  M2 is the rule for bare rows whose opener test is
  `nonspace_at`.  Quotes (`DBareAfterBreak`) use `dopens_after` and are
  out; `DBraced` rows are only ever marked, so only clauses 1, 2 and 4
  apply to them.  State over the table's rows, as the other inline
  theorems do.
- **Whitespace is `is_space`.**  Check it against the reference's
  "whitespace" and djot.js (tabs, CR) before stating; the coverage row
  should name the set.
- **`spot_before` is sound only for tokens without a break** (its
  comment).  Delimiter tokens qualify; a marked opener's `{` and token
  are on one line.  Keep the lemma restricted to that.
- **Span convention.**  Our image span starts at `!`, djot.js's at `[`
  (F1).  For emphasis, check with `djotjs-sourcepos.mjs` that djot.js's
  span covers both delimiters, braces included, so the statement agrees
  with the oracle's notion of a node's extent.
- **Erasure is the bridge.**  Do not restate anything at
  `semantic_pos`; the located statement plus `para_inlines_at_erase` is
  the whole claim.
