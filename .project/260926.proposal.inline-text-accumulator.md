# Proposal: accumulate pending inline text without copying its prefix

## Problem

Pending inline text is a `string`, and it grows by `txt ++ piece`.
Extracted to a native OCaml string, each append copies everything
pending so far, so a line whose text grows in n small appends costs
O(n^2). The text is flushed at every line break (`ibreak_flat`), so the
cost is quadratic in line length, not paragraph length.

Two paths append:

- the Gallina step: every byte of pending text that goes through
  `istep` in text mode, such as `ilead`'s fallback arm, `iperiod_step`,
  or the decay of `IDash`, `IBang`, and `IClosed`;
- the native drivers in `extraction/Extract.v`: a batch of letters,
  digits, and spaces appends with `txt ^ String.sub s i (j - i)`, which
  copies the prefix once per batch.

A line of `.a` pairs takes the first path at every byte. A line of
`word, ` alternates between the two. Measured 2026-09-26 at `7884839`,
dev profile, `convert --time 3`, semantic block parse:

| shape, one line | 20 KB | 80 KB | growth |
| --- | --- | --- | --- |
| `.a` | 16.0 ms | 133.1 ms | 8.3x |
| `word, ` | 5.0 ms | 49.7 ms | 10x |
| 15 words, then `x, ` | 1.3 ms | 7.5 ms | 5.9x |
| `word ` (from `extracted-performance.md`) | 1.7 ms | 4.8 ms | 2.8x |

The `word ` row never leaves a native batch, and it is near linear, so
the block side handles a long line in linear time. The growth in the
other rows is the inline scan.

## Intended result

Appending a byte or a piece to pending text costs time proportional to
the piece. Asking whether pending text is empty costs constant time in
practice. The text becomes a flat string only when it is emitted or a
rule needs its value.

The semantic and located parsers produce the same nodes, text,
attributes, and source spans as now. `prev` stays a separate field: it
names the last source byte, which the pending text cannot give back
once typography has substituted into it.

## Design

### The scanner is generic over pending text

`iscan_g` has the constructors of today's scanner state, with every
pending-text field of type `P`, including in the recursive shadow
states. Verbatim content (`IVerb`, `IRaw`), destinations, labels, and
attribute source stay `string`. The step, line break, finish, and the
helpers that rebuild text (`bflat`, `bsplit_nl`, `bclosed_lit`,
`bspan_lit`, `battr_lit`, `bref_lit`, `iescws_resolve`) take the
operations as a typeclass:

```coq
Class TextOps (P : Type) := {
  tnil : P;
  tpush : P -> string -> P;
  tof : string -> P;
  tval : P -> string;
  tnonempty : P -> bool
}.
```

`iscan` names `iscan_g` at `string`, and that instance is the
specification. It is supplied as a literal record with primitive
projections, not a named constant, so a restricted `cbn` reduces
`tpush txt s` to `txt ++ s` with no extra unfolding. It is also the
default instance when `P` is undetermined, which keeps binders such as
`forall st, ... is_compound st ...` inferring as before. A tactic
`tred` rewrites the operations to their string meaning in the goal and
hypotheses, for proofs that `unfold` rather than `cbn`.

### The execution instance

Pending text for execution is a list of chunks, newest first:

```coq
Definition ptext := list string.
tnil := []
tpush b s := if nonempty_str s then s :: b else b
tof s := tpush [] s
tval b := String.concat EmptyString (List.rev b)
tnonempty b := existsb nonempty_str b
```

Laws, proved once for the instance:

```coq
tval tnil = EmptyString
tval (tpush b s) = (tval b ++ s)%string
tval (tof s) = s
tnonempty b = nonempty_str (tval b)
```

Because `tpush` never stores an empty chunk, `existsb` stops at the
head, so `note_pos`, which asks on every `[` and `^`, stays constant
time. Chunks rather than `list ascii` because a native batch is one
`String.sub` pushed as one chunk. `String.concat` and `List.rev` are
native, so `tval` is linear.

### Simulation

`map_text : iscan_g P -> iscan` sends every pending-text field through
`tval` and recurses into shadow states; `lift : iscan -> iscan_g P`
does the same with `tof`, and `map_text (lift st) = st`. The
simulation is proved for any instance satisfying the four laws, so the
same lemmas serve the semantic and the located scanners:

```coq
map_text (istep_at attrs c q) = istep_at attrs c (map_text q)
map_text (ibreak_at attrs q) = ibreak_at attrs (map_text q)
ifinish q = ifinish (map_text q)
```

Each helper gets its own commuting lemma first. Line-scan equivalence
follows by induction.

### Routing and extraction

The parser reaches the scanner through three line drivers, `iscan_str`,
`iscan_str_off`, and `iscan_str_located`, and each already has a
trusted native realization. They stay the Gallina specification, and
no caller changes. Each gets a `ptext` counterpart and a theorem:

```coq
iscan_str s st = map_text (iscan_str_p s (lift st))
```

The native realization of each driver becomes `lift`, an offset loop
over the `ptext` scanner, and `map_text`. The batch arm pushes its
`String.sub` as one chunk. The trusted part is the same as today: the
offset loop against the Gallina `ptext` driver. The conversions cost
the pending text once per line, and text pending across a line break
is bounded by one line.

## Limits

Some fallbacks still take the whole pending value, once per failed
construct: a failed autolink candidate (`auto_lit` through
`blit_prev`), and a failed `{` or span spec (`battr_lit`, `bspan_lit`
through `blit_prev`). A line of repeated failed candidates, such as
`<a <a <a`, therefore stays quadratic. `blit_prev` needs only the last
byte of the rebuilt piece, which never depends on the pending text, so
each can be rewritten to avoid `tval` in a follow-up.

Verbatim, raw, destination, label, and attribute-source accumulators
still append to strings, and structural string matches in `Line`,
`Strings`, `Attributes`, `Marker`, and inline helpers still copy tails
after extraction. `isnoc` and `osnoc` merge adjacent `Str` nodes with
`t ++ s`. `key_scan` runs its own per-byte scan. Measure long-line
shapes for each after this change before calling the long-line issue
fixed. The same `TextOps` parameter may serve the other accumulators.
