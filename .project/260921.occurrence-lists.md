# Occurrence lists

Step 7 of `260916.plan.source-locations.md`: link and anchor occurrence
lists on the located document. What downstream asks for is "every place
this label is used, and where it is defined", which is a rename's input
and a go-to-definition's answer.

## What exists

Definitions are collected by `doc_pass` (`Document.v:1073`), which runs
`assign_ids_list`, `collect_notes_list` and `collect_refs_list` and
fills a `doc` (`Ast.v:1160`).

Not one of the three keeps a position.

- `add_ref` (`Document.v:682`) takes the definition's `pos` and drops
  it. `reference_map` is `list (string * (string * attr))`
  (`Ast.v:1150`), so a reference holds its destination and attributes
  and nothing else.
- `collect_notes` (`Document.v:782`) removes the `FootnoteDef` node and
  stores the cleaned body under the normalized label, so the
  definition's span goes with the node. The body blocks keep theirs.
- A heading's generated id is a synthesized string (`Document.v:199`).
  It is not authored, so it has no span and never will; the anchor a
  consumer wants is the heading's own span, which it has.

On the use side no label or destination span is recorded separately.
A direct link is one node over `[...](...)` (`Inline.v:3961`) and its
destination accumulates as a plain string (`Inline.v:3240`). A
reference link and a footnote reference keep the opening `[` as
`open : span` in `IReference` (`Inline.v:3212`) and `INote`
(`Inline.v:3225`) and emit one node over the whole construct. The
label's inline children have spans; the brackets, the second bracket's
label text and the destination do not.

The role vocabulary is three constructors (`Ast.v:212`): `RAttrSpec`,
`ROpenFence`, `RCloseFence`.

## The decision

Two shapes, and they are not equally priced.

**Widen `reference_map`'s value.** Its value type is consumed by
`lookup_reference` (`Ast.v:1155`), which is name resolution, and by the
renderer's `doc_references ++ doc_auto_references` (`Html.v:785`).
Positions are not resolution data, and widening makes every lookup site
carry them. Rejected unless something below forces it.

**Add a field to `doc`.** An occurrence list beside the maps, keyed the
same way. The cost is `empty_doc`, the `Doc` application in `doc_pass`,
and whatever the three standing theorems over `doc_pass` demand of one
more component: `wf_doc_pass` (`Wf.v:4585`), `roundtrip_doc_pass`
(`Roundtrip.v:2332`) and `undo_pass_doc_pass` (`Document.v:2422`).
Check each before writing the field, per the standing-quantifier rule.

At the semantic instance the list has to be empty, so that the
document-level refinement is the identity on it. That is the
[[project-engineering-lessons#Erasure is a left inverse of both sides]]
check: ask the policy before recording, do not record and discard.

## The obligation that is already missing

There is no document-level erasure theorem. `parse_doc_located`
(`Document.v:1097`) is `doc_pass` at the located instance and nothing
relates it to `parse_doc`; the refinement stops at
`parse_blocks_located_erase`. An occurrence list is the first thing
that would make its absence load-bearing, because it is the first `doc`
field whose value differs between the instances. Prove
`erase_doc (parse_doc_located s) = parse_doc s` first, with the fields
as they are, and the field lands into a shape that already has a
statement to satisfy.

## Open, and decided with this and not before

A soft break's span runs to the start of the next line's content, so it
covers the terminator and the next line's container prefix
(`260916.plan.source-locations.md` section 6, C4). It is filed as an
API concern. It is the same question as what an occurrence's span
covers, so it is answered here or it is answered twice.
