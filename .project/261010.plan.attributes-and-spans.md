# Plan: attributes and spans in the inline specification

## Goal

Stage 3 of [[261007.plan.inline-specification]]: inline attribute specs
and spans (AT1, AT6, AT7, C2, N1) in `Precedence.v`, with
`para_inlines_valid` keeping its statement and `over_alphabet` admitting
`{` beyond a delimiter marker and `]{` as a bracket closer.

## How the scanner reads them

- **A spec** begins at a `{` that no row's character follows, while
  inline attributes are on (`ibrace_step_at`).  Its bytes go to the
  block attribute machine (`astep`, `AttrSyntax.v`); the ordinary
  reading of the same bytes runs beside it as a shadow (`IAttr`,
  `iattr_feed`).  On success the spec becomes a mark in the scope
  (`omark`); on failure the scanner takes the shadow, which may be
  several bytes on.
- **A mark attaches late.**  When the scope resolves, each mark lands
  on what sits before it in the resolved list (`oattach_list`): the
  last word of a plain `Str`, merging with nothing when the spec is
  empty; any other node, merging attributes; nothing after whitespace,
  after a soft break, or at the start of the scope.  The resolved list
  depends on how the openers before it ended: in `_a{.c}` with the `_`
  never closing, the `_` is text and joins the word, so the spec lands
  on `_a`, not on `a`.
- **A span** is a bracket that closes with `]{`: the bracket's content
  and a spec read by the same machine (`ISpan`, `ispan_feed`); on
  failure the brackets and the spec's source are text.
- **A spec may cross a line break** (AT6); the machine reads the newline
  as whitespace.

## What stage 2 settles

The reading is on byte offsets and a construct can be one token
(`tok_at`).  A spec that closes is a token of the same kind as a raw
spec; a span's `]{` is a bracket closer like `](` and `][`, with the
spec as its region.

## Decisions

Decided 2026-10-10: D1 (a), D2 (a), D3 (b).

**D1. Specs that fail.**

- **(a) Leave them out, decided.**  The alphabet admits a `{` that
  no row's character follows only where a spec that closes begins, as
  stage 2 did for raw specs.  The shadow then never decides, and a
  failed spec's bytes never need a reading.
- **(b) Take them in.**  A failed spec is its ordinary reading.  The
  simulation would carry the attempt as a layer that falls away when it
  fails, as `wrap` carries destinations that never close.  More proof,
  and `{` before most bytes would enter the alphabet.

(b) is left for a later pass and (a) does not stand in its way.  Whether
a spec closes is a function of the bytes from its `{`, so (b) only
changes `tok_at` at a `{` whose spec fails, to the text `{`, and loosens
`over_alphabet`.  The work is in the simulation, which has to carry the
attempt and its shadow until the attempt ends.  Stage 2 left out the
same shape for a `:` before a run of symbol characters that does not
close, so one pass can take both.

**D2. Where a spec attaches.**

- **(a) State attachment in the tree, decided.**  `tree_of` keeps a
  mark in the frame and resolves it when the frame closes.  The
  reference asks that a spec "*immediately follow* the inline element to
  which they are attached (with no intervening whitespace)"; which
  element that is, a word when the text before it is plain, is the
  scanner's (`oattach_list`), and this states it.  The view (`pview`)
  gains the same marks, and the simulation ties `oresolve` to the tree's
  resolution.  This is the larger change, and the one that states the
  rule.
- **(b) Restrict the alphabet to fixed targets.**  Admit a spec only
  where its target cannot change: right after a node that is not text
  (a closed delimiter, a verbatim, a link), or after a word whose start
  is fixed.  The tree attaches at once.  Smaller, but the theorem stays
  T~ on the shape the reference cares most about.

(b) is not a step towards (a): the tree would attach at once under (b)
and hold the mark under (a), so going through (b) rewrites `tree_of`'s
part and its lemmas.

Under (a) the rule is stated from the reference, not copied from
`oattach_list`, in four cases: after plain text the target is its last
word; after any other node it is that node; after whitespace or a soft
break there is none; at the start of a frame there is none.

**D3. Specs across lines (AT6).**

- **(a) Include them**, with the spec walked byte by byte across the
  break, as a verbatim is (`PMAtom`).
- **(b) Leave a newline out of specs for now, decided.**  A spec is
  then one token within a line, read by `scan_tok`; AT6 stays where it
  is (T~ through the attribute grammar).
