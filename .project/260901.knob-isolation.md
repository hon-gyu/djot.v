# Knob isolation: what is proved, and what the document-level statement costs

Date: 2026-09-01. Companion to the "Where a setting is read" section of
`theories/Invariants.v`.

## The property

A configurable parser wants two facts about every setting: it has an
effect, and it has a *bounded* sphere of effect. The second, stated at
document level, reads

```
outside setting K's trigger language,
  parse (config with K = false) s = parse (config with K = true) s
```

## What is proved now

Per query, not per document. `Invariants.v` pins where each of the eight
boolean block settings is read:

| setting | read in | at |
| --- | --- | --- |
| `btables` | `open_kind` | `KRow` |
| `bdivs` | `open_kind` | `KDiv` |
| `battrs` | `open_attr` | `KAttr` |
| `bfootnotes` | `open_foot` | `KFoot` |
| `btasks` | `configured_list_*` | `KList` |
| `bheading_continues` | `step_fuel` | state `PHeading` |
| `braw_blocks` | `fence_block` | info string starting `=` |
| `bdeflists` | `styles_list` | head style `SBullet ":"` |

and states, for each, the negative half: five cannot change what a line
opens (`_opens_only_*`, `_opens_nothing`), five cannot change what a
state closes to (`_finishes_nothing`), and the last two are guarded by
the construct's own spelling. Eight `Example`s give the positive half,
one document each.

The list of queries is the complete set of places `step_fuel` reads the
block configuration: `open_line` (covering `open_kind`, `open_attr`,
`open_foot` and the list-marker projections), `bunderline_of`,
`binterrupt`, `bheading_continues`, `finish`, and `fence_block`. Every
other function it calls -- `is_lazy`, `feed_lazy`, `blank_absorbed`,
`div_closer`, `in_fence`, `fence_close`, `caption_open`, `ref_cont`,
`list_next`, `list_content`, `list_blank`, `pend_result`, `is_idle`,
`table_block`, `foot_block`, `div_block`, `ref_block` -- takes no
`bconfig`, which `Check` reports.

## What the document-level statement needs

Two pieces, and the first is the one that decides the cost.

**A descent predicate.** The trigger for the five line-triggered
settings is a *kind*, and a kind can arise at any depth of the container
descent: `> | a |` reaches `KRow` through a quote prefix. `step_fuel`'s
recursion descends on exactly three kinds -- `KQuote rest`,
`KList _ _ chk rest` (through `configured_list_rest`), and `KFoot _ rest`
-- so the predicate is a fuel'd fixpoint over that chain, ~20 lines. It
is cheap to write and it has to be threaded through the induction below,
which is where it is paid for.

**A conditional congruence for `step_fuel`.** The unconditional version
-- two configurations agreeing on all the queries above give the same
`step` -- is provable by induction on the fuel, and `finish_config_ext`
suggests the branches are mechanical. It is also *useless*: no setting
satisfies its hypotheses, because every setting has an effect, so the
theorem would have no consumers. The version with consumers has the
`open_line` hypothesis restricted to kinds off the trigger, and then the
induction must carry the descent predicate through every recursive call
-- including the ones that pass an `inner` state rather than a fresh
line.

**And a state predicate for three of them.** `bheading_continues` is
triggered by a *state*, not a line, so its statement needs "no `PHeading`
anywhere in the state tree", preserved across the descent.
`braw_blocks` and `bdeflists` are read from `finish`, so theirs are "no
`PFence` with a raw info string" and "no list state whose surviving style
is a colon bullet" -- again state predicates, and the second is not
stable under `narrow`, which is the awkward one.

## Estimate

Eight settings, three shapes of predicate, one shared induction. Not a
sitting's work: the induction over `step_fuel` is ~270 lines of
definition with twelve state branches, and the descent predicate has to
survive all of them. Before starting it, check the cheaper question
first -- whether the five line-triggered settings can share a single
parameterized predicate, since they differ only in which kind is
forbidden. If they can, the induction is written once and the eight
theorems are instances; if not, the step is eight inductions and should
be reconsidered.
