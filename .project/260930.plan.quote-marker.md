# Plan: the block quote marker (BQ1)

## Goal

Raise BQ1 in `syntax-reference-coverage.md` from T~ to T:

> A block quote is a sequence of lines, each of which begins with `>`,
> followed either by a space or by the end of the line.

Today only the canonical spellings are proved: `> ` on any line
(`classify_canonical_quote`, `classify_canonical_quote_pad`) and a bare
`>` on an empty line after the first (`step_quote_bare`).  This is the
smallest of the plans written on 2026-09-30, and a good first task in
the codebase.

## Statements

Names are suggestions.

1. **Line level, both directions.**

   ```
   classify l = KQuote r  <->
     exists pre, is_blank pre = true /\
       (l = pre ++ ">" /\ r = ""
        \/ exists c, is_ws c = true /\ l = pre ++ String ">" (String c r))
   ```

   The right-to-left direction is the reference's rule; left-to-right
   says nothing else is a quote line (`>x` is not).  Check what `is_ws`
   admits: the reference says "a space", and if a tab also counts that
   is a gap to log, not a reason to weaken the statement.

2. **Optional: a bare `>` as the first line.**  BQ2's notes say a quote
   whose first line is a bare `>` opens the same quote but is not
   stated, because it records a different source range.  With positions
   erased (`semantic_pos`) the statement `quote_uniformity` should hold
   for it too.  Worth doing only if 1 goes quickly.

## Pitfalls

- `classify` tests `is_blank` first, so `pre ++ ">"` is nonblank but
  `pre` alone is blank; the statement needs `l` nonblank, which the
  `>` guarantees.
- With the callout extension on, a quote line can carry a header
  (`quote_header`); that changes the block built, not the line's kind,
  so statement 1 needs no callout hypothesis.
