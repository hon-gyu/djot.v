# Plan: source locations

## 0. Goal

Close the source-location feature gap between the extracted parser and
oymarkit.  A caller that asks for locations should be able to associate an
authored block or inline node with the bytes that produced it, and to find the
source spelling of attached attributes, references, and footnotes.  Parsing
without locations remains available.

The semantic boundary is:

```coq
erase_locations (parse_blocks_located source) = parse_blocks source
```

and likewise after the document pass.  Locations describe one parse of one
source buffer.  They are not stable identities, are not part of the canonical
AST equality, and are not reproduced by rendering a node in isolation.

This distinction corrects the conclusion in `260902.document-model.md`.
That note correctly observes that putting context-dependent positions in
`cb_ast` would break the canonical roundtrip statement.  It does not follow
that parsed source provenance must be absent.  Canonical syntax remains
positionless; located parse output is a refinement that erases to it.

## 1. Baseline

`Ast.pos` currently has the intended-looking shape
`NoPos | SomePos sl sc el ec`, but the parser does not construct `SomePos`.
`mk` is `Node NoPos []`, and the explicit attributed-node constructors use
`Node NoPos` too.

The information needed to do better is discarded before node construction:

1. `Strings.split_lines` returns `list string`, with no absolute byte start or
   source line number.
2. `Step.step_fuel` strips quote and list prefixes and accumulates only the
   remaining strings in `pstate`.
3. `Inline.para_inlines` receives those stripped strings.  `iscan_str` has no
   cursor, and opener frames remember syntax but not where the opener was.
4. `Document.doc_pass` synthesizes `Section` nodes and removes reference and
   footnote definition blocks into maps whose entries carry no provenance.

Oymarkit's relevant contract is optional locations (`~locs:true`) containing
absolute byte ranges and line information.  Its block-attribute wrapper has a
range beginning at the first attribute specifier, while the wrapped block has
its own narrower range.  That distinction supports navigation to `{#id}`,
rename, and duplicate diagnostics.  DjotV attaches attributes directly to a
node, so it needs explicit attribute provenance rather than trying to fit both
ranges into one `pos`.

## 2. Contract to settle before changing the parser

The first checkpoint is a small executable location corpus, run against the
current oymarkit checkout.  Record both byte ranges and the source substring
for each range.  It must cover:

- a paragraph, heading, code fence, quote, list item, div, and table;
- nesting at least two containers deep;
- escapes and smart punctuation, where AST text differs from source text;
- emphasis, verbatim, links, images, references, and footnote references;
- constructs spanning a line break;
- block and inline attributes, including stacked and multiline specs;
- attribute failure/recovery and an unattached block spec;
- reference and footnote definitions before `doc_pass` removes them;
- an empty source, trailing newline, blank lines, CRLF, and non-ASCII UTF-8.

Do not infer range boundaries from the prose spec.  Ask the oracle, then pin
the contract in focused examples before implementation.

### 2.1 Proposed representation

Absolute half-open byte ranges are authoritative:

```coq
Record source_span : Type := SourceSpan {
  span_start : nat;
  span_stop : nat
}.
```

`span_start <= span_stop`; `span_stop` is the first byte after the construct.
Half-open ranges compose without `+ 1`, represent empty authored regions, and
map directly to mdast offsets.  Line and column are derived from a document
line index rather than copied into every node.  A file/source identifier is
document metadata, not repeated in each span.

The existing `pos` should not merely gain four populated `nat`s.  Replace it
with provenance that can distinguish the semantic node from its attached
syntax:

```coq
Inductive source_role : Type := AttributeSpec.

Record provenance : Type := Provenance {
  node_span : source_span;
  syntax_spans : list (source_role * source_span)
}.

Inductive pos : Type :=
  | NoPos
  | SomePos (origin : provenance).
```

`syntax_spans` is deliberately role-tagged rather than a bare list so another
source-only spelling is not later smuggled in as “another attribute”.  Add a
new role only with a demonstrated consumer and an oracle-backed range.

This is a proposal until the corpus answers the boundary questions.  In
particular, check whether one span per complete attribute spec is sufficient
for rename.  If a consumer needs the exact span of each key or value, model
that explicitly rather than reparsing `syntax_spans` downstream.

### 2.2 Range rules

The expected rules, subject to the oracle corpus, are:

- A node covers the complete source construct, including its own opener and
  closer, but not a trailing line ending that merely separates blocks.
- A child inside a quote or list starts after the container prefix; the
  container covers its markers as well as its children.
- A normalized `Str` covers the source bytes that produced it, not the bytes
  of the normalized value.  Thus an escape and a smart-punctuation sequence
  may have a wider source span than their AST text.
- Merging adjacent `Str` nodes takes the hull of their contiguous source
  spans.  Never merge non-contiguous spans merely because their values are
  adjacent in the AST.
- Attached attributes do not widen `node_span`; their source is recorded in
  `syntax_spans`.  This gives the information represented by oymarkit's wide
  wrapper and narrow child without changing DjotV's semantic AST shape.
- Synthesized `Section` nodes remain `NoPos`; their authored heading and body
  children retain locations.  A generated container is not assigned a source
  range by taking a convenient hull.

The last two rules are DjotV representation decisions, not claims that its AST
must have the same shape as oymarkit's.

### 2.3 Line and column API

The parser should expose absolute byte spans first.  A document-level line
index converts a byte offset to `(line, column)`.  Pin whether columns are byte
columns or Unicode scalar columns; oymarkit's mdast lowering currently derives
columns from byte offsets, and byte columns are the extraction-friendly first
contract.

Do not silently change line syntax while adding locations.  DjotV currently
splits on LF and treats CR as intra-line whitespace.  Supporting bare CR as a
line ending is a separate semantic change.  CRLF location tests must reflect
the parser that exists.

## 3. Architecture: one parser, two observations

A located parser copied from `Step` or `Inline` would drift as soon as a
grammar branch changes.  Do not add `lstep` as a second match tower and do not
reparse the finished AST to guess locations.

The implementation should make source slices the shared input to the existing
branch decisions:

```coq
Record source_slice : Type := SourceSlice {
  slice_text : string;
  slice_span : source_span
}.
```

Dropping a known number of source bytes returns a smaller slice with an
advanced start.  Classification continues to inspect `slice_text`; origin
operations do not decide syntax.

The parser core may be parameterized by a small metadata policy, or may carry
optional provenance internally and erase it at the old entry points.  Choose
between those only after the checkpoint below.  The required properties are:

- there is one syntactic dispatch for each block and inline byte;
- location-off parsing does not maintain a second semantic state;
- the old `step`, `parse_lines`, `parse_blocks`, and `para_inlines` interfaces
  can remain proof-facing wrappers until their users are migrated;
- erasure is structural and does not rerun the parser;
- extraction exposes separate location-off and location-on entry points.

### 3.1 Architectural checkpoint

Before converting the whole state, implement a throwaway-or-promotable probe
for these inputs:

```djot
> - a [link](dest){.c}
```

and

```djot
{#wide
  .class}
> paragraph
```

The probe must produce the semantic result and exact source spans, including
the nested inline and attribute spec.  Its erasure must compute to the current
parse result.  Use it to compare:

1. a shared slice-aware core with a metadata policy;
2. always carrying optional provenance and erasing at the public old API.

Reject an approach if it duplicates the grammar, requires locations in
canonical `cblock`/`cinline`, or makes ordinary semantic lemmas quantify over
irrelevant cursor arithmetic.  Record the chosen shape and the measured proof
impact in this file before proceeding.

## 4. Implementation sequence

Each step ends with a focused build and an erasure check.  Do not start the
next layer while the current layer has only example equality and no general
projection lemma.

### 4.1 Source spans and located line splitting

Add the span/provenance definitions and recursive location erasure for inline
nodes, block nodes, blocks, maps, and documents.  Prove erasure idempotent.

Add a located line splitter that retains each line's absolute start and the
line-ending width.  Prove:

```coq
map slice_text (split_source_lines s) = split_lines s
```

and prove bounds, ordering, and non-overlap of its spans.  Extraction may use a
native implementation only after the same equivalence procedure used for
`split_lines` in `extracted-performance.md`.

### 4.2 Block locations

Thread slices through block classification and prefix removal.  Every open
container state needs enough origin to construct its final range:

- paragraph and heading slices;
- fence opener, body, and closer;
- quote/list/div/container start and last claimed source byte;
- table rows and caption;
- reference and footnote definition opener and continuations;
- keyed-block label and claimed block;
- block-attribute slices through success, pending attachment, and recovery.

The existing `off` argument is an absolute *column within a line*.  It is a
constraint used by `step_fuel_shift` and `step_fuel_pad`; it is not a document
byte offset and must not be repurposed.  Source-slice movement is a separate
operation whose erasure leaves those theorems' semantic statement unchanged.

Required result:

```coq
erase_blocks (parse_blocks_located s) = parse_blocks s
```

Also establish that every returned source span is within the input and that a
located child is contained in its authored container where the AST represents
that containment.

### 4.3 Inline locations

Pass paragraph source slices, not reconstructed strings, from the block layer
to the inline layer.  Across a soft break, the next slice supplies the new
absolute cursor; do not compute it from normalized inline content.

Add origins to the scanner data that defer decisions:

- pending literal text;
- delimiter, bracket, destination, reference, span, and verbatim openers;
- attribute candidates and their ordinary-reading shadows;
- output frames used for close-below-top and fallback.

Closing a construct takes its start from the retained opener and its stop from
the consumed closer.  Literal fallback uses the complete abandoned source
region.  `osnoc`/`isnoc` must merge both text and source ranges consistently.

Required results:

```coq
erase_inlines (para_inlines_located slices) =
  para_inlines (map slice_text slices)
```

and the corresponding statement for the leading-lines-attributes-off path.
The existing no-reread certificate remains about semantic source dispatch;
location accounting must not introduce a second scan.

### 4.4 Attribute provenance

On successful block or inline attachment, transfer the completed spec's span
to the target node's `syntax_spans` while keeping `node_span` narrow.  Preserve
one entry per authored spec and its source order across merged/stacked specs.

On recovery, the spec bytes belong to the recovered text nodes and do not
remain attribute provenance.  An unattached completed block spec needs an
occurrence in the located parse result even though the semantic parser emits
no block.  Decide at the contract checkpoint whether this is a source-event
side table or an explicit located-only node; it must erase to nothing.

### 4.5 Document pass and occurrences

`doc_pass` must preserve locations while it:

- assigns heading identifiers;
- collects reference definitions;
- extracts footnote definitions;
- synthesizes sections.

Do not overload the existing semantic `reference_map` and `note_map` with
editor concerns.  Add a located document result containing the semantic
`doc` plus authored occurrences, for example:

```coq
Record located_doc : Type := LocatedDoc {
  located_semantic : doc;
  located_blocks : blocks;
  located_anchors : list anchor_occurrence;
  located_links : list link_occurrence;
  located_references : list reference_occurrence;
  located_footnotes : list footnote_occurrence
}.
```

The exact fields follow actual consumers, not this sketch.  Preserve duplicate
occurrences in document order.  Resolution belongs above this layer; parsing
reports what was authored and where.

Prove that `located_semantic` is the current `parse_doc` result after erasure.
Generated documents that need authored occurrences must still be serialized
and reparsed; a generated AST does not acquire fictional source locations.

### 4.6 Extraction and public API

Keep the current location-off entry points.  Add explicit location-on entry
points rather than a global setting hidden in extraction glue.  Expose:

- byte-span accessors;
- line-index construction and byte-to-line/column conversion;
- node provenance and attribute-spec spans;
- authored occurrence lists from `located_doc`.

If mdast JSON is emitted here, use 1-based line/column and 0-based half-open
offsets at that boundary.  Keep those presentation conventions out of the
parser's core types.

## 5. Proof boundary

The core verified claims are:

1. located parsing erases to semantic parsing;
2. spans are ordered and bounded by the input;
3. located line splitting projects to current line splitting;
4. structural transformations in `doc_pass` preserve authored child
   provenance and do not invent provenance for generated nodes.

Exact agreement with oymarkit's span choices is an executable differential
contract, not a theorem about the external implementation.  Pin representative
cases locally and keep the comparison harness deterministic.

The canonical roundtrip theorem remains exactly about positionless semantic
ASTs.  Do not weaken it to equality modulo positions and do not add positions
to `cblock` or `cinline`.  No `Admitted` is acceptable for the erasure bridge;
without that bridge the located parser is an unverified second parser.

## 6. Performance boundary

Feature parity is the priority, but the location-off path must not regress by
accident.  Measure separately:

- current semantic parse;
- new location-off parse;
- location-on parse;
- oymarkit with `locs:false` and `locs:true`.

Per-byte `nat` cursor increments may allocate unary naturals in extracted
OCaml.  The architectural checkpoint must inspect this rather than assuming
Rocq cost matches extraction cost.  Prefer advancing from source-slice starts
and consumed lengths at syntactic boundaries over maintaining unnecessary
line/column counters for every byte.  Any native offset primitive would join
the trusted extraction boundary and needs the equivalence testing required by
`extracted-performance.md`; it is not part of the first implementation.

## 7. Validation matrix

Focused validation at each checkpoint:

- `dune build` for the affected theory and dependents;
- the general erasure theorem, not only examples;
- `make test` and `make roundtrip` after block and inline milestones;
- the generated canonical sweep, confirming positions do not change semantic
  acceptance or rendering;
- exact range fixtures for every construct listed in §2;
- bounds and parent/child containment checks over generated small inputs;
- `git diff --check`.

Before declaring full parity:

- run the complete build;
- compare the pinned corpus with oymarkit location-on output;
- inspect location-off and location-on performance on ordinary prose, a long
  paragraph, a long line, and nested containers;
- verify the extracted public API from a separate OCaml consumer;
- update `Overview.v`, `260907.ARCHITECTURE.md`, and
  `extracted-performance.md` with the new verified and measured boundaries.

## 8. Milestones and stop conditions

1. **Contract pinned.** Oracle fixtures decide ranges and attribute
   provenance.  Stop if the consumer requires per-token attribute positions;
   widen the metadata design before implementation.
2. **Architecture proved on hard witnesses.** One shared syntax dispatch
   produces nested block, inline, and attribute spans and erases to the current
   result.  Stop if the design duplicates parser branches.
3. **Located block parser.** General block erasure and span bounds pass.
4. **Located inline parser.** General inline erasure passes, including
   recovery and cross-line constructs.
5. **Located document API.** References, footnotes, anchors, and links retain
   authored occurrences through `doc_pass`.
6. **Extraction and parity.** Public API, differential fixtures, full tests,
   and both performance modes pass.

The useful intermediate deliverable is milestone 5, not “some nodes now have
`SomePos`”.  It closes the navigation/rename/diagnostic gap even if exhaustive
mdast position emission is finished afterward.

## 9. Non-goals

- Stable identity across edits.  Use explicit ids and higher-level document
  operations for that.
- Lossless source layout or concrete-syntax-tree preservation.
- Changing Djot semantics while plumbing locations, including bare-CR line
  handling.
- Giving generated sections, TOCs, or other synthesized nodes fake authored
  spans.
- Matching oymarkit's internal AST wrapper shape.
- Improving parser speed as part of the feature.  Performance regressions are
  measured and bounded, but optimization is a separate direction.
