# Plan: inline precedence (P1, P5)

## Goal

Raise two rows of `syntax-reference-coverage.md` from E to T:

| Row | Reference ("Precedence") |
| --- | --- |
| P1 | "the first opener that gets closed takes precedence.  Containers can't overlap, so once an opener gets closed, any potential openers between the opener and the closer get marked as regular text and can no longer open inline syntax" |
| P5 | "When there are multiple openers that might be matched with a given closer, the closest one is used" |

Unlike the block rows done so far, these cannot be stated as an
equation of the parser in the reference's own terms: the reference
describes a *matching* between openers and closers, and the parser has
no such object.  `oclose_go` walks the scope stack from the top and
abandons every frame it passes, which is P1 and P5 as an algorithm; a
theorem about `oclose_go` would be an equation of the code, which the
coverage file does not count.  So the work is to write the matching the
reference describes as its own small model, and prove the parser
agrees with it.

## Approach

Three layers, each small enough to review on its own.

1. **Tokens.**  A line over a restricted alphabet read as a list of
   tokens: text, or a delimiter with its style, whether it may open and
   whether it may close.  "May open" and "may close" are the reference's
   flanking rules (M2: not followed / not preceded by whitespace), read
   off the neighbouring bytes, not off the scanner.
2. **The reference matching, declaratively.**  A set of (opener,
   closer) index pairs is *valid* for a token list when:
   - each pair has the same style, `i < j`, the opener may open and the
     closer may close (and, once braces are in, the same marking: P4);
   - no two pairs cross (containers can't overlap);
   - each pair encloses something besides delimiters of its own style
     (M3; needed so that `___` comes out right);
   - **P5**: no opener of the pair's style strictly between `i` and `j`
     is still live at `j`;
   - **P1**: a closer that may close and is left unmatched has no live
     opener of its style, or the closest one would enclose nothing (so
     `__a` has no pair: the second `_` fails to close and opens);

   where an opener is *live at* `j` if it is unmatched before `j` and
   not inside a pair that closed before `j` (the "marked as regular
   text" clause).  A token is used as a closer, an opener, or text,
   never two of these.

   Prove that a valid matching exists and is unique, by giving
   `ref_match`, a left-to-right function over the token list written
   from the prose, and showing it is valid and that any two valid
   matchings are equal.  The uniqueness theorem is what makes the
   predicate, rather than `ref_match`, the specification.
3. **The parser agrees.**  `tree_of toks m` builds inlines from a token
   list and a matching: a pair becomes the style's node around what it
   encloses, and everything else is text.  The main theorem:

   ```
   para_inlines [s] = tree_of (tokens s) (ref_match (tokens s))
   ```

   for `s` over the alphabet.  Proof by a simulation between the
   scanner's `ostate` and `ref_match`'s state, one byte at a time.

P1 and P5 are then corollaries in the reference's words: for every `s`
over the alphabet, the nodes of `para_inlines [s]` are the pairs of the
unique valid matching, so the parser closes the first opener that gets
closed and uses the closest one.

- **Stage 4 (optional)**: brackets.  P1's own examples include
  `[Link *](url)*` and `*Emphasis [*](url)`, so brackets are in the
  rule, but they add a second token family, destinations as barriers
  (`fr_barrier`, `oclose_barred`), and the discard and close-below-top

Smart quotes (`DBareAfterBreak`) are out of every stage: an unmatched
quote is a curly quote rather than text, and whether it may open
depends on the byte before it.  Say so in the notes.

## Pitfalls

- **An empty matching frame stops the walk** (`oclose_go`): the closer
  fails and may open instead, and does *not* look further down for
  another opener.  That is "the closest one is used" taken literally,
  together with M3.  The model must say the same; check it on `___a___`
  (three nested spans, per the `oclose_go` comment; confirm with
  djot.js) before fixing the predicate.
- **Closing wins over opening**, and a failed close may open
  (`idelim_resolve`).  The token's role is decided by the matching, so
  the model must not fix it from flanking alone.
- **M3 counts abandoned scopes.**  `oclose_go` tests the content
  including the literals of the scopes it abandoned, so in stage 3 a
  marked closer walking past an unmarked `_` closes over it (`{__}`).
  The model's "besides delimiters of its own style" says otherwise;
  settle it with djot.js when stage 3 starts.
- **Text merging.**  The scanner merges adjacent `Str` nodes
  (`no_adjacent_str`, `isnoc`).  `tree_of` must merge the same way, or
  the theorem must compare after a normalization; decide in stage 2,
  and prefer making `tree_of` merge.
- **A spec-only scope** is the one source of an empty delimiter node
  (the `oclose_go` comment).  Keep `{` out of the alphabet until stage 3
  and attribute specs out altogether.
- **Lines.**  `para_inlines` scans a paragraph's lines as one text with
  a break between them, and a line break is whitespace for flanking.
  State stage 2 for one line; lifting to several is a follow-up.
- **The table.**  The scanner is read at a `dtable`.  State the model
  over the table's `DBare` rows so that the theorem holds for the whole
  family, as the other inline theorems do; `with_*_preserves_admissible`
  shows which tables are in scope.
- **Positions.**  State everything at `semantic_pos`.
- **Do not transcribe `oclose_go` into `ref_match`.**  The model is
  allowed to be a stack too (the prose is sequential), but it should
  read from the reference: tokens and indices, not frames and
  `oitems`.  Stage 1's uniqueness theorem is the check that it says
  what the prose says and nothing about the code.

How the proof goes:
- A *prefix view* (`pview`, `pstep`): the live openers with the content

  `rstep` keeping content, so its live list is `rstep`'s.
- Model side (`tree_of_prun`): `tree_go` with the whole line's matching

  `valid` and the fact that `ref_match` grows by closers supply.
- Scanner side (`scan_sim`): the scanner's `ostate` is the view embedded
