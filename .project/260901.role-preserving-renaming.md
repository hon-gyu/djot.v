# Role-preserving renaming: the precondition, and what the theorem still costs

Date: 2026-09-01.

## The property

Visibly pushdown languages are closed under renaming only when the
renaming preserves the call/return/internal partition; unrestricted
renaming loses the property. The parser-side reading is

```
parse_{T[k := d]} (swap c d s) = swap_inlines c d (parse_T s)
```

where `c = dc_char T k` and `swap c d` exchanges the two characters
everywhere. A table is a family only if its rows can be respelled, and
this is the statement that says so.

## What the probe found

`dconfig_ok` is not that precondition, and the gap was not the one the
comment on the admissibility conditions expected.

**The hyphen.** A row spelled `-` and declaring itself `DBare` was
admissible. `ilead` claims the hyphen before it consults the table, so
such a row is reached from `{` and from `}` and from nowhere else:
`{-x-}` marked the span while `-x-` was a smart dash, on the same table.
Condition 4 is documented as "a row's character is not one the scanner
claims for itself ... a row spelled with one would never be reached",
and `dreserved` lists every character `ilead` dispatches on except this
one -- deliberately, because djot's own delete row is `-` and is
braced. `drow_ok` now carries the syntax-conditional form:
`dsyntax_bare` rows may not be spelled with the hyphen, braced rows may.
`ilead_dchar_bare` is what the condition buys, and
`bare_hyphen_incompatible` / `braced_hyphen_row_ok` are the boundary.

**The block layer.** Spelling emphasis `>` is admissible and stays
admissible: `>` is punctuation, is not reserved, and collides with no
row. It is claimed by `classify` instead, at line start, so under that
table `>a> b` is emphasis in a paragraph and `> a> b` is a block quote
whose content begins with an unmatched closer. The inline table's
admissibility is silent about the block layer's claims, and it should
stay silent: the block claim is positional (`*` and `-` are delimiter
characters *and* list markers today, and nothing is wrong with that).
What follows is about where the renaming theorem can be stated, not
about a further condition.

## The theorem, and its cost

State it at `para_inlines`, not at `parse_doc`. A character the block
layer claims at line start moves line classification, and no condition
on the delimiter table can prevent that without forbidding `*` and `-`,
which djot itself uses for both.

Three pieces, in cost order.

1. **The swap.** A character exchange over strings, then over `inlines`
   -- every string in the tree, not only `Str`: `Verbatim`, link
   destinations, attribute values, raw formats. Mechanical, and the
   inline AST is what fixes its size.

2. **The scanner commutation.** An induction over `iscan_str`, which is
   the large one. The swap has to commute with every character test the
   scanner makes: `is_punct`, `is_ws`, `is_bslash`, `is_tick`,
   `dreserved`, `dopens_after`, and `dstyle_of`. The first six are
   preserved because both characters are punctuation and neither is
   reserved -- which is `drow_ok`, so admissibility does most of the
   work. `dstyle_of` is where the renaming is *used*: it is the lookup
   whose answer moves, and the induction's real content is that it moves
   consistently.

3. **The side conditions.** `dconfig_ok` of the renamed table, which
   `update_drow_preserves_admissible` already gives from
   `drow_update_compatible`; and the target character not already
   spelling an enabled row, which is `dconfig_distinct`.

The estimate is dominated by (2), and it is not a sitting's work:
`iscan_str` dispatches through `ilead`, `istep` and a state type with a
dozen constructors, and the swap has to be pushed through each. Before
starting it, do the cheaper thing first -- write the swap and check the
equation by `vm_compute` over a spread of sources, as `bare_hyphen`
above was found. A counterexample at that stage is worth more than the
induction.
