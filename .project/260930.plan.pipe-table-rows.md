# Plan: pipe table rows (PT1, PT2, PT7)

## Goal

Raise three rows of `syntax-reference-coverage.md` from E to T.  All
three are statements about one line, `Line.table_row`, so no parser
state is involved.

| Row | Reference |
| --- | --- |
| PT1 | "Each row starts and ends with a pipe character (`\|`) and contains one or more *cells* separated by pipe characters" |
| PT2 | a separator line: "every cell consists of a sequence of one of more `-` characters, optionally prefixed and/or suffixed by a `:`" |
| PT7 | "backslash-escaped pipes and pipes in verbatim spans ... do not count as cell separators" |

## Statements

Names are suggestions.

1. **PT1, only if.**  `table_row l = Some r` implies the first nonblank
   character of `l` is `|`, its last is `|`, and they are different
   positions.  Follows from `row_body`.

2. **PT1, if.**  For cells `cs <> []` of plain text (no `|`, no
   backslash, no backtick, no leading or trailing whitespace), the line
   `"|" ++ concat (map (fun c => " " ++ c ++ " |") cs)` gives
   `Some (TCells cs)`, unless it is a separator line.  Pick "plain" to
   make the proof go through, and say in the doc comment what it
   excludes.

3. **PT2, only if.**  `table_row l = Some (TSep als)` implies the body
   is a sequence of cells each of the form `:?-+:?`, with the
   whitespace the scan admits.  Together with `separator_row_alignments`
   this characterizes separators.  State it as an inverse of
   `separator_text`: some list of `(left, right, n)` triples renders to
   the body.

4. **PT7.**  Inside a cell, `\|` and a verbatim span containing `|`
   stay in the cell.  For plain `a`, `b`, `x`, `y` (as in 2):

   ```
   table_row ("| " ++ a ++ "\|" ++ b ++ " |") = Some (TCells [a ++ "\|" ++ b])
   table_row ("| `" ++ x ++ "|" ++ y ++ "` |") = Some (TCells ["`" ++ x ++ "|" ++ y ++ "`"])
   ```

   A stronger form, over any cell text whose escapes and verbatim spans
   are balanced, is welcome but not required.

## Pitfalls

These are pinned by examples in `Line.v`; the statements must not
contradict them.

- `| --- |` is a row of cells, not a separator: a separator cell's
  leading whitespace belongs to the previous cell's match, so the first
  cell cannot have any (`row_sep_leading_space`; `SPEC-GAP` 2026-08-02).
- A row whose verbatim span is never closed is not a row at all
  (`row_verbatim_unclosed`, `row_double_backslash_before_backtick`).
- An escaped final bar leaves the row without its closing bar
  (`row_escaped_final_bar`).
- `\ ` at a cell's end keeps the space (`row_escaped_space`); trimming
  is a parity test on backslashes.
- `sep_cells` and the scans run on fuel; the house style is to state
  results without fuel, using the `_fuel_more` style lemmas that
  `separator_row_alignments` already uses.
