# Attaching an inline attribute after the scan, not during it

## The gap

An inline attribute spec attaches to the run of text before it. djot.js
decides that in a pass over the *resolved* match stream, so by the time
it asks "what is before this?", an opener that never found its partner
is already ordinary text. We ask during the scan, while the opener is
still an open scope.

```
a *b{#id key="*"}o     djot.js  a <span …>*b</span>o
                       ours     a *<span …>b</span>o
```

`attributes.test:31` is one instance. Fourteen shapes were probed
against djot.js; **eight differ**, and they are all the same thing — an
unfinished `*`, `_`, `[` or `![` immediately before a spec:

| input | djot.js | ours |
| --- | --- | --- |
| `a *_b{.c}o` | `<span class="c">*_b</span>o` | `*_<span class="c">b</span>o` |
| `a **b{.c}o` | `<span class="c">**b</span>o` | `**<span class="c">b</span>o` |
| `a [x{.c}o` | `<span class="c">[x</span>o` | `[<span class="c">x</span>o` |
| `[a{.c}b] c` | `<span class="c">[a</span>b] c` | `[<span class="c">a</span>b] c` |
| `*b{.c}` | `<span class="c">*b</span>` | `*<span class="c">b</span>` |
| `a *{.c}o` | `<span class="c">*</span>o` | `*{.c}o` (no attach at all) |

**The boundary.** When the opener *closes*, the two agree exactly —
`a *b{#id key="x"}o*`, `a *b{.c}o* d` and `a *b{.c}* d` all match today,
verified through the harness. So this is not a disagreement about where
a spec attaches; it is a disagreement about *when*, and no answer
available at the `}` is the right one, because whether the `*` closes is
not yet known.

**A local repair does not work.** The obvious fix — when an abandoned
opener goes back as text, glue it onto the attributed word next to it —
is refuted by `az*b{.c}o`, which djot.js renders `<span
class="c">az*b</span>o`. The attributed word reaches back *past* the
opener into text flushed before the scope was ever pushed.

**And this is not the same implementation technique.** djot.js re-reads
input for the unfinished destination (`links_and_images:220`) and the
unclosed spec (`attributes:370`); this repair rewrites only our own
output. Later analysis in [[no-backtracking]] corrected the stronger
conclusion drawn from that fact: both oracle results can be computed by
advancing an ordinary-inline shadow beside the special candidate,
so both remain compatible with no-backtracking even though djot.js uses
replay to obtain them.

## The design

A scope accumulates `oitem`s rather than nodes:

```coq
Inductive oitem := OIn (n : node inline) | OMark (a : attr) (src : string).
```

`iattr_mark` flushes the pending text and drops an `OMark` where the
spec closed. `oresolve : oitems -> inlines` walks a scope's list
tail-first, so each marker sees the already-resolved item immediately
before it, and applies djot.js's `-attributes` rule (`parse.ts:446-506`)
to it. Resolution runs at three points: `oclose` (a delimiter scope
becomes a node), `bclose` (a bracket's label becomes a node's children)
and `ofinish` (the paragraph ends, after every abandoned opener has
become text).

Traced by hand against all fourteen probes, this reproduces djot.js on
every one, including the ones that already pass:

- `a b*c*d{.e}f` — the `*c*` closed, so it is a node; the marker stops
  there and takes `d`.
- `a *{.c}b*` — the `*` closed and the marker is first inside it with
  nothing before: dropped, which is what djot.js does.
- `After {#id} space` / `{.class}` — the marker's predecessor is the
  `SoftBreak`, which takes it and renders as nothing. **This closes
  `attributes:95` as well.**
- `{#id} at beginning` — nothing before it at all. djot.js drops it; we
  cannot, because `# {#i}` would be a heading with no children, so the
  marker's own source is printed. `attributes:89` stays divergent, and
  it is the only one that does.

Expected corpus: **282 -> 284/287**, with the three left all adjudicated.

## What was measured

**The invariant lemma is cheap.** `.project/artifacts/260822.deferred-attach.probe.v`
defines the element type and the pass and proves that resolution
preserves `oscope_ok`. Twenty lines, first attempt, closed under the
global context, reusing `ilist_ok_ocur`, `ilist_ok_reattr`,
`plain_str_reattr`, `oscope_ok_set_cur`, `oscope_ok_emit_merge` and
`ilist_ok_tail`.

**It also simplifies the scan.** `oresolve` rebuilds a scope's list with
merging emission, so it re-establishes "no two adjacent plain `Str`s" by
construction. What it asks of its input is only that every node is
well-formed and every marker's source is nonempty — no adjacency
condition. The seam obligation currently threaded through every scanner
state (`negb (hd_str (ocur o))` in `iscan_wf`) therefore has nothing left
to protect.

**Census of what has to move.** Eight definitions inspect the
constructor of an output element and need one arm each — `osnoc`,
`starts_str`, `opop_str` (two), `bflat`, and `plain_str` / `hd_str` /
`oscope_ok` on the well-formedness side. Forty `_app` lemmas mention the
output list but only *carry* elements. `oemit` keeps its `node inline`
argument and wraps, so most call sites do not move at all.

## The two costs the census did not predict

Both were found by starting the edit; the partial work is
`.project/artifacts/260822.deferred-attach.wip.patch` (586 lines, the
definitional half of `Inline.v`, not compiling).

**1. Resolution is not the identity, so the equations about closing a
scope acquire a side condition.** `oclose_oemit_all_marked` and
`bclose_oemit_all` say that a scope built by `oemit_all` out of settled
nodes closes back to exactly those nodes. That is now true only when no
two plain `Str`s were put next to each other, since `oresolve` would
merge them. Both lemmas need `no_adjacent_str (rev ns)`, and so do their
~10 users in the `iscan_marked_*` family. This also forces `plain_str`
and `no_adjacent_str` out of `Wf.v` and into `Inline.v`, which the WIP
patch does; the two new lemmas it needs (`isnoc_cons`, `oresolve_map`)
are five lines each and are already written and compiling.

**2. Markers cross a line break, so the line decomposition needs a new
condition.** `ibreak_closed` says a closed line's state is the finished
inlines of that line with a `SoftBreak` on top, and
`para_inlines_cons2_closed` uses it to split a paragraph into
independent lines. A pending marker breaks that: resolved as part of the
whole paragraph, a marker at the start of line 2 sees line 1's
`SoftBreak` and vanishes; resolved line-by-line it sees nothing and
prints its source. So `iscan_closed` needs a "no pending marker"
conjunct, and `ibreak_closed` probably needs `iscan_wf` as a hypothesis.
Both lemmas have exactly two users, both about canonical text, which
never opens a spec — so both discharge, but it is a statement change
rather than a proof change.

*Resolving at the break instead is not an option.* `a *b{.c}` / `o*`
closes the `*` on line 2; the marker must still be able to see the `*`
decay if it never closes.

## Predictions, and what happened

Obligation-shaped, so that a failure names the thing that went wrong.
Two of four held.

- **Held.** No statement outside `Inline.v` and `Wf.v` acquires a
  hypothesis — the diff touches exactly those two files.
- **Held, in a different form.** "The roundtrip needs one new lemma:
  `oresolve` is the identity on canonical output." That lemma is
  `oresolve_map`, and it is what the canonical-view proofs rewrite with;
  the roundtrip itself needed no change.
- **False.** "`iscan_wf` *loses* a conjunct." It keeps the seam
  condition, and that is *why* the step got cheaper rather than dearer —
  see below.
- **False.** "`base_ok` can revert to the weaker `starts_str base =
  false`." `oresolve_app` still needs the suffix headed by a
  `SoftBreak`, so the strengthening stands; deferring the attachment
  moved the query rather than removing it.

## Both predicted costs were avoided, by two changes found while editing

**The equations.** The plan said `oclose_oemit_all_marked`,
`bclose_oemit_all` and their ten users would acquire a
`no_adjacent_str` side condition, because a merging pass is not the
identity. They did — for about an hour. Then `oresolve_go` gained a
boolean: a node is *consed* onto what is already resolved, and merged
only when the item just below it was a spec that resolved to nothing.
That is the only place two plain `Str`s can meet, so resolution became
the identity on a marker-free list **definitionally**
(`oresolve_map` needs no hypothesis), and every side condition came
back out. The scan keeps its seam obligation to pay for it, which is
the prediction that was wrong.

**The line break.** The plan said `iscan_closed` would need a "no
pending marker" conjunct, because a spec at the start of line 2 sees
line 1's `SoftBreak` when the paragraph is resolved whole and sees
nothing when it is resolved line by line. Keeping `oattach_list`'s
refusal of a `SoftBreak` head — the rule `oattach` already had, for the
`oout_app` splice — makes the two agree, and the whole `_app` family
goes through untouched. The price is `attributes:95`, which was already
adjudicated as ours for exactly this reason.

## What is left

`attributes:89` and `a *{.c}b*`: a spec with nothing before it in its
own scope, where dropping would leave an empty container. Forced.

`[a{.c}b] c`: a spec inside a bracket that decays, since `bclose` must
hand `IClosed` resolved children. Logged in `oracle-disagreements.md`
and pinned by `Inline.attr_inside_a_decaying_bracket`.
