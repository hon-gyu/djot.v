# The nested-list bug, and what fixing it costs

A confirmed parser bug, its fix design, and a measured estimate of the
migration. Written after a reconnaissance spike; the spike is on
`spike/column-offset` (commit `4d8e524`, deliberately does not build).

## The bug

Input:

```
- - b
  - c
```

Both oracles read one outer item containing a **two**-item inner list.
Ours reads a **one**-item inner list and swallows `- c` into it. Logged in
`oracle-disagreements.md` under "Adjudicated 2026-08-08 — ours"; it is the
first entry where our parser is the one at fault.

Root cause: `step_fuel` descends into a marker's residue with
`step_fuel n' rest (PPara [])`. A nested `open_list` there records
`indent_of rest` — an indent in the *residue's* coordinates. For `- - b`
the inner list is recorded at indent 0 although its marker sits at column
2, so `  - c` (indent 2) tests as *content* of the inner item rather than
a sibling of it. Both oracles measure the nested marker's absolute column.

This is not exotic: it is the canonical rendering of any `CList` whose
item begins with a nested `CList`, so it blocks nested lists in the
roundtrip for a reason that is nothing to do with proof difficulty.

## The fix

Thread a column offset through the parser:

```coq
Fixpoint step_fuel (n : nat) (off : nat) (l : string) (st : pstate) ...
```

- `off` is added at the two places indentation is consulted:
  `open_list (off + indent_of l)` and the routing test
  `Nat.ltb (ls_indent ls) (off + indent_of l)`.
- Every descent through a consumed prefix (quote prefix, list marker)
  passes `off + consumed l rest`, where
  `consumed l rest = String.length l - String.length rest`.
- Descents that keep the line (a list item's contents) pass `off`
  unchanged.
- `step` is the `off = 0` instance.

Rejected alternative: pad the residue back out with spaces instead of
threading a number. It reads better but breaks termination — the measure
is line length plus stack depth, and a space-padded residue has the same
length as the line it came from, so the descent no longer decreases
anything.

## What it costs, measured

The spike got as far as the fuel lemmas. `step_fuel_stable` and
`step_fuel_enough` generalize mechanically (the offset does not enter the
measure); a `step_fuel_enough_off` variant is needed because only the
outermost call runs at offset 0.

The build then stops at `step_quote_open`, and that is the real boundary.
**Six descent lemmas become false as stated**: `step_quote_open`,
`step_quote_cont`, `step_list_open`, `step_list_sibling`,
`step_list_diffstyle`, `step_list_quote_close`. Each relates
`step l st` to `step rest st'`, i.e. an offset-0 run to another offset-0
run, whereas the descent now happens at `consumed l rest`.

They are not merely broken; they are broken *by a shift*. The right
restatement is modulo `pad_state`:

```coq
step rest (PPara []) = (bs, inner) ->
step l (PPara []) = ([], PQuote (rev bs) (pad_state (consumed l rest) inner))
```

which needs the shift theorem as a prerequisite:

```coq
step_fuel n (k + off) l st
= (fst (step_fuel n off l st), pad_state k (snd (step_fuel n off l st)))
```

**This is the theorem `step_pad` should have been.** Once every list
indent derives from `off + indent_of`, adding `k` to the offset adds `k`
to every recorded indent, and the shift *is* uniform — including for
nested lists. `pad_state` then recurses everywhere (no stopping at
`PQuote`, since a quote's inner indents become absolute too), and
`pad_inner_ok` disappears along with the nested-list exclusion. The
obstacle recorded in `260807.list-roundtrip-indent-shift.autonomous.md`
is a symptom of this bug, not an inherent difficulty.

Downstream, `Roundtrip.v` has **39 occurrences of `LSt 0`** — the
top-level list at column 0 — and its list machinery is built around that
constant. Two mitigations make this less bad than it looks:

- Flat top-level lists run entirely at `off = 0`, so `LSt 0` stays
  correct for everything currently proven.
- The six descent lemmas hold *unchanged* whenever the inner state has no
  recorded indent to shift — precisely today's `pad_inner_ok`. So they can
  keep their present statements plus that hypothesis, discharged
  trivially in every existing call site, and gain `pad_state` forms only
  where nesting needs them.

Estimate: the parser change is an afternoon; the shift theorem is
comparable to `step_fuel_pad` (which is done and can be adapted); the
descent-lemma restatement and its propagation through `Roundtrip.v` is
the bulk, and is the part that wants a session of its own with the build
green at each step.

## Suggested order

1. Land the parser change with the six descent lemmas carrying a
   `pad_inner_ok` hypothesis, keeping every existing proof intact. Verify
   `- - b` / `  - c` against both oracles and re-run the corpus.
2. Prove the offset-shift theorem, adapting `step_fuel_pad`. Retire
   `step_pad`, `pad_safe`, `pad_inner_ok` and
   `pad_nested_list_unshifted` — the last of which should *fail* to
   compile once the bug is fixed, which is the cleanest possible
   confirmation.
3. Restate the descent lemmas modulo `pad_state`, then generalize
   `Roundtrip.v`'s list lemmas from `LSt 0` to `LSt k`.
4. Nested lists in the roundtrip then need only `list_content_safe`
   relaxed to still exclude fences but admit `CList`.

Do not start step 3 without finishing step 2; the restatement is
unmotivated without the shift theorem to discharge it.
