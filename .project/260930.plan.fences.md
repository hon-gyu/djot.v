## Statements

Names are suggestions.

1. **Closer lines, CB2.**  For backticks, `fence_close (Fence "`" n
   info) (pre ++ backtick_run m ++ post) = Nat.leb n m` with `pre` and
   `post` blank.  This is the reference's "equal or greater in length";
   a shorter run is then content by `parse_lines_fence_content`.

2. **Whole code block, CB2.**  For an opener `l` with `classify l =
   KFence f`, content lines none of which closes `f`, and a closer `c`:

   ```
   parse_lines (l :: content ++ c :: rest)
   = fence_block f (map (drop_ws_upto (indent_of l)) content)
     :: parse_lines rest
   ```

   The `drop_ws_upto` is the opener's indentation, removed from each
   content line.  State it with `line_texts`/`remember_lines` if that
   matches `parse_lines_fence_seed` better; the statement above is the
   one to aim for.  Also the unclosed form, ending at the end of input.

3. **Raw blocks, RB1.**  With `braw_blocks = true`, the same document
   with info `=fmt` gives `RawBlock fmt` with the joined content.  One
   corollary of 2.

4. **Div opener, DV1.**  `classify (pre ++ colons (3 + n) ++ gap ++ cls
   ++ post) = KDiv (3 + n) cls` for blank `pre`, `post`, blank `gap`
   (nonempty when `cls` is), and `cls` of class characters
   (`is_class_char`).  Mirror `classify_backtick_fences`.  The converse,
   that `classify l = KDiv n cls` only for such lines, is worth stating
   too; it is where "but nothing else" lives.

5. **Div closer and whole div, DV2.**  Generalize `run_div_open`,
   `parse_lines_div_cont` and `div_uniformity_tail` from `3` and
   `EmptyString` to any length `len` and class, with a closer line of
   `m >= len` colons.  The side condition stays `run_div_open len`:
   a line inside the contents that would close the div is excluded,
   because it does close it.

## Pitfalls

- Tilde fences are accepted (`SPEC-GAP` 2026-08-02, see CB1).  State
  CB2 for backticks as the reference does; a tilde variant is optional.
- A closer's indentation is ignored (`fence_close_ws_prefix`), and so
  is a div closer's (`div_close_ws_prefix`).  The statements should
  allow a blank `pre`.
- `::: foo` opens a div and never closes one; a closer carries no class.
- Inside an open code block a `:::` line is content, not a div closer
  (`in_fence`).  The generalized div lemma keeps the
  `in_fence (snd (run_lines content inner)) = false` hypothesis.
- `bdivs` and `braw_blocks` are configuration switches; carry them as
  hypotheses.
