# Plan: a less conservative canonical renderer

## Goal

Make `Render.render_djot` write text closer to what a person would type,
without giving up the round trip it proves.  Today its output is correct
and hard to read:

```
Note\: see [docs](https\://example\.com/x\_y)\. Ratio 3\:1, {_fine_}, snake\_case.
```

The cause is that every spelling decision is made without context, which
is what keeps the proofs short.  Each relaxation below replaces one
context-free decision with a local one and carries its own proof
obligation.  They are independent and ordered by value over cost.

## What exists

- `InlineView.needs_escape`: the set a `Str` escapes.  Reserved
  characters, every delimiter character of the table, `^`, `-`, `:`.
- `InlineView.bare_ok` and `escape_from`: the one relaxation already
  made.  `.`, `!` and `-` go bare depending on the next byte and on
  whether the run ends its line.  This is the pattern to repeat.
- `InlineView.needs_escape_dest`, `escape_dest`: a link destination
  escapes `needs_escape` plus the two parens.
- `InlineView.marked_open`, `marked_close`: a span's delimiters are
  always braced.
- `InlineInvert.v`: the scanner inversion.  `iscan_dest_escape` is the
  destination lemma; the `Str` lemmas go through `escape_from`.
- `Readable.bare_ok`: the rule for writing a span's delimiters bare,
  used by the unproved readable renderer.  It follows
  `InlineScan.idelim_resolve` and is the candidate statement for step 4.
- `ListUniformity.indent_lines`, `Line.quote_line`: the container
  prefix, put in front of every line, blank ones included.

## Steps

### 1. Link destinations

The destination mode (`InlineScan`, the `IDest` arms of `istep_at`)
dispatches on three bytes only: `\`, `(` and `)`.  The unescaped branch
of `iscan_dest_escape` already uses nothing else (`Hbs`, `Hlp`, `Hrp`).

Change `needs_escape_dest` to those three bytes.  `needs_escape_dest_punct`
stays true.  Expected to be close to a definition change.

Check before starting: the other users of `needs_escape_dest` in
`InlineTable.v` and `Site.v`, and whether anything relies on a
destination's escapes when the link fails to close and the bytes are
read as ordinary text (the `sh` shadow state).

Optional follow-up: balanced parens go bare, since the mode counts
depth.  Needs a balance predicate on the destination.

### 2. The colon

`:` is escaped everywhere because it can start a symbol (`:name:`) and,
with keyed blocks on, can end a key.  Neither applies to most colons.

Extend `bare_ok` with a colon case.  The statement has two parts:

- inline: a `:` whose following bytes do not form `name:` opens no
  symbol.  Find the exact condition in the scanner's symbol arm.
- block: a paragraph line holding a bare `:` still classifies as text.
  With `Ext_keyed` on this is `Render.key_inline_ok`'s territory, so the
  colon may have to stay escaped under that setting, or bare only when
  not followed by a space.

### 3. Delimiter characters between spaces

A delimiter character with whitespace on both sides can neither open
(`nonspace_at next` fails) nor close (`nonspace_at before` fails), so
`a * b` needs no escape.  A local fact about `idelim_resolve` and
`idelim_done`, stated through `bare_ok`'s `pre` and `rest`.

The first character of a run still escapes, since it may start a line
where `* ` is a list marker.

### 4. Bare span delimiters

Write `_a_` for `{_a_}` when `Readable.bare_ok` holds.  This is the
hard one.  The inversion proofs use the fact that a braced delimiter
opens and closes on sight.  A bare closer goes through `oclose_reaches`
and `oclose`, so the proof has to carry what is on the scanner's stack:
that the nearest opener of the row is the span's own.

Do this only after 1 to 3, and only if the remaining gap justifies it.
The readable renderer already covers trees built by hand.

### 5. Delimiter characters inside words

`snake_case` needs no escape when no other `_` in the paragraph can pair
with it.  This depends on the whole paragraph, not on neighbours, and
has no local statement.  Not planned.  Listed so that nobody mistakes it
for a variant of step 3.

## Related: blank lines inside containers

`indent_lines` and `quote_line` prefix blank lines, so the output has
lines holding only spaces, or `> ` with a trailing space.  The fix is to
leave a blank line empty (bare `>` in a quote).

The uniformity proofs are stated over "the prefix on every line"
(`ListUniformity.v`, `OrderedList.v`, `Uniformity.v`, `Roundtrip.v`,
about 90 references to `litem_lines` and 40 to `quote_line`).  The
missing lemma: a blank line steps the same with or without the pad.
That needs an invariant on open code fences, since a fence at a smaller
indent would keep the pad as content.  `step_quote_bare` is the existing
fact for quotes.

A post-pass that strips whitespace-only lines is unsound: it also
changes whitespace-only lines inside code blocks.

## Pitfalls

- Every relaxation must hold for the table in force, not for djot's
  spelling.  `bare_ok` is read under `Context {T : dtable}`.
- `needs_escape` has obligations of its own (an escaped character is
  punctuation; the backslash escapes itself).  Keep them.
- The round trip is proved for the fragment `cb_ok` accepts.  A
  relaxation that shrinks that fragment is a regression even if the
  theorem still closes.  Compare the accepted counts in
  `test/roundtrip.ml` before and after.
- Use rocq-mcp for the inversion lemmas.

## Alternative that needs no proof

Write the readable form, parse it once, and use the canonical form for
any paragraph whose tree differs.  The guarantee comes from the check.
If that mode ships first, steps 4 and 5 lose most of their value, and
steps 1 to 3 remain worth doing because they improve the fallback.
