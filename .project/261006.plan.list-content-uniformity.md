## Goal

`list_uniformity` (ListUniformity.v) proves two things at once: each
item's contents parse as its lines do at top level, and the list's
spacing is `list_spacing_of` of those lines.  Its hypothesis `items_ok`
asks `item_ok` of every item, and `item_ok` includes `run_safe` and
`item_end_ok`.  Those exclude any item with a block attribute outside a
block quote, an item that ends inside a code block, and an item that
ends on a blank line.  So the README lists list and definition list
uniformity as conditional (commits 0afc543, 6d15d29).

Split the theorem so that the contents half needs only the item's shape,
and `run_safe` stays on the spacing half, where the tightness property
already states it.  Then the two uniformity rows go back to proved.

## What `run_safe` is used for now

- `scan_loose_eq`, `scan_blanks_last`, `scan_blanks_item`, `scan_shape`:
  the list state's loose and blanks fields in closed form.  This is
  spacing only.
- `run_safe_final`, giving `blank_safe` of the state an item ends in.
  `parse_list_tail` and `parse_item_and_tail_narrow` carry
  `blank_safe inner` as an invariant for three uses:
  - `step_blank_finish`, for the loose separator blank and for the blank
    before a closing line (`parse_list_close`);
  - `blank_safe_attr_waits`, to clear `list_settle` (spacing only);
  - `key_claims_not_claimable` and `step_blank_key_claims`, to show the
    next marker line is not claimed by a key inside the item.

The contents themselves come from `run_lines_list_cont` and
`run_lines_pad_shift`, which have no side condition.

`step_blank_finish` fails as an equation for the open fence and the open
spec, but only on states.  On blocks it holds in both cases:

- an unclosed fence's `finish` applies `drop_blank_lines` (Step.v,
  `finish`), so a blank added to it changes nothing;
- a blank fails an open spec, which emits the paragraph that `finish`
  would have emitted.

## Statement

Split `item_ok` in two:

    item_shape_ok m L   (* nonblank first line, marker line not thematic,
                           no task shadow *)
    item_spacing_ok L   (* run_safe of the rest, item_end_ok of the last *)
    item_ok m L = item_shape_ok m L && item_spacing_ok L

and `items_shape_ok` beside `items_ok`.  Then

    list_content_uniformity :
      forall m0 sp L0 tail,
        marker_ok m0 = true ->
        items_shape_ok m0 ((m0, L0) :: tail) = true ->
        parse_lines (list_lines sp (map litem_lines ((m0, L0) :: tail))) (PPara [])
        = [marker_list_checked m0 (list_scan_spacing m0 sp ((m0, L0) :: tail))
             (map (fun it => mk_check (fst it)) ((m0, L0) :: tail))
             (map (fun it => parse_lines (snd it) (PPara [])) ((m0, L0) :: tail))]

where `list_scan_spacing` is the spacing the parser's own scan reaches
(the loose field of the final `scan_list_content` state, folded over the
items and separators).  It is a definition, not an existential, so the
spacing half is an equation about it:

    list_scan_spacing_of :
      items_ok m0 items = true ->
      list_scan_spacing m0 sp items = list_spacing_of sp (map snd items)

and `list_uniformity` keeps its statement, as the two composed.  Nothing
downstream that uses `list_uniformity` changes (OrderedList.v,
Render.v, Roundtrip.v, Properties.v's `list_uniform`).

Rejected: stating the contents half with `exists sp'`.  It is shorter,
but the spacing half would then need its own induction over the same
items, which is the duplication this plan exists to remove.

## Risks

- Keyed blocks.  The key lemmas are where `blank_safe` does real work;
  stage 1.3 decides whether the content theorem holds for every
  configuration or only with keys off.
- `list_scan_spacing` has to be a fold the conclusion can name without
  the list state the proof threads.  If it cannot be stated from the
  items alone, it falls back to `exists sp'` plus a separate spacing
  induction, which this plan rejected for duplication.
- The `_tail` ending after an item left inside an open fence or spec:
  the closing line must still close the list.  Covered by stage 1.2.
