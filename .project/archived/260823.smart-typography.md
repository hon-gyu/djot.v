# Smart typography as an inline capability

## Boundary

Add one boolean capability to `dconfig` for the two hardwired text
rewrites: period triples become an ellipsis and hyphen runs become en/em
dashes.  Curly quotes stay delimiter rows: the Markdown-like profile already
switches those off independently, and merging rows with scanner dispatch
would erase a useful existing boundary.

Djot and `markdown_config` keep typography enabled.  The narrower
`markdown_like_config` disables it, so `...`, `--`, and `---` remain literal.

## Parser shape

Keep `IPeriod` and `IDash` at both settings.  This preserves the scanner's
one-byte dispatch and its existing single-pass/locality proofs.  In
particular `IDash` must remain: even with typography disabled, a run before
`}` may give the delete delimiter its closer back when that row is enabled.
Only resolution changes:

- the third period emits `ellipsis` when enabled and `...` when disabled;
- a completed hyphen run emits `dashes n` when enabled and `n` literal
  hyphens when disabled.

## Proof obligations and witnesses

- Row updates and disables preserve the capability field.
- `with_smart_typography` preserves delimiter admissibility, since the
  boolean does not affect row validity or trigger distinctness.
- The generic inline single-pass and classification-locality results remain
  parametric without new hypotheses.
- Existing Djot punctuation examples remain unchanged.
- `check/Markdown.v` pins literal periods and hyphens under the reduced
  profile, and applies the existing roundtrip theorem at that profile.

No canonical-view predicate needs widening: punctuation was already escaped
by the renderer because scanner dispatch reserves `.` and `-`.  Disabling the
rewrite changes how user source parses without changing canonical source.
