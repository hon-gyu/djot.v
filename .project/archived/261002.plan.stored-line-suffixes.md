# Plan: inline content is a slice of its source line

## Goal

Finish stage 4 of `261002.plan.inline-flanking.md`: lift M2 and M3 from
"every paragraph's and cell's content" to "every document", so their
rows in `syntax-reference-coverage.md` say "over every document" with no
gap.

`para_inlines_spans` and `cell_inlines_spans` state the rules on windows:
the text the block layer hands the inline scanner, with the `rem` each
window starts at.  The lift needs two facts the code assumes and nothing
proves (`260916.plan.source-locations.md`, F2):

1. every stored line `(k, t)` a state keeps is a suffix of source line
   `k`, so a spot `(k, rem)` inside it names the same byte in the
   source;
2. every table cell's recorded start locates its trimmed text in its
   row's line.

## Statement

For a source `s` and its lines `L := split_lines s`, read each line whole
as a window: `src_windows L := [(k, length L_k, L_k) | k]`.  Then, with
key blocks off,

    Forall (blocks_dn (src_windows L)) (parse_blocks_located s)

where `blocks_dn W` holds of a block when every inline sequence in it
(paragraph, heading, caption, cells, definition terms, callout title, key
label), at any depth, satisfies `Forall (dn_node W)`.

The source form says no less than the window form.  Every byte clauses 1
to 4 read lies inside the content window (the byte after a bare opener
and the byte before a bare closer must exist there), and a window
embedded in its source line reads those bytes the same.  At a window's
left edge the content has no byte, so the scanner never closes there;
the source's container prefix is never consulted.  So the step from
windows to source is one monotonicity lemma:

    windows_embed W W' -> dn_node W n -> dn_node W' n

where `windows_embed W W'` says each `(k, r, w)` of `W` has `r` at most
the length of `W'`'s line `k`, and the line from `r` bytes before its end
starts with `w`.

Keys are left out because a retracted key builds its paragraph with
`para_inlines [src]`, the semantic scan, so its delimiter nodes carry no
position.  That is a statement about keys, not a gap in the lift; note it
beside `key_split_contract`.

### Stage 2: line-level suffixes

`is_sfx t l := exists p, l = p ++ t`.  Lemmas, in `Line.v` or a small new
file:

- `drop_leading_ws l`, `drop_ws_upto n l` are suffixes of `l`;
- the `rest` of `KQuote`, `KList`, `KFoot`, `KHeading` is a suffix of `l`,
  and so is `configured_list_rest chk rest`;
- `caption_open l = Some rest`: `rest` is a suffix;
- `callout_header rest = Some (_, _, title)`: `title` is a suffix of
  `rest`;
- transitivity.

### Stage 3: the state invariant

`stored_ok L i st`: every stored line `(k, t)` in `st` (paragraph,
recovered paragraph, heading, caption, attribute slices, callout title)
has `k < i` and `t` a suffix of `L_k`, and every accumulator is strictly
decreasing in `k`.

Preservation: if `stored_ok L i st` and the line handed to `step` at
`lix = i` is a suffix of `L_i`, then the state `step` returns satisfies
`stored_ok L (S i)`.  By induction on the fuel, as `step_fuel_erase` is.
Every descent passes a suffix of its line (stage 2), and every
`remember_line` stores a suffix of the line it is given.

### Stage 4: what is emitted

`blocks_dn (src_windows L)` for every block `step` and `finish` emit,
from a state with `stored_ok`.  Each inline producer:

- `para_inlines_at k (rev cur)`: `para_inlines_spans`, then
  `windows_embed` from `stored_ok` (`para_windows` takes each stored
  line whole, and the last one stripped, which is a prefix of it);
- `callout_title`: `cell_inlines_spans` at `rem := length source`;
- cells: `cell_inlines_spans` at the row part's `rem`, which needs
  `table_row_part l (TCells cs) = Some p` whenever `classify l = KRow
  (TCells cs)`, with one part per cell, each locating its cell in
  `drop_leading_ws l` (a `row_cells_trace` lemma in `Line.v`); and that
  `PTable` keeps one row part per `TCells` row, in order;
- `key_label`: as cells, from the key's start.

Then the block-moving operations (`set_pos`, `decorate_head`,
`add_roles_head`, `def_items`, `task_items`, `list_block`) keep
`blocks_dn`, each by a short lemma over the inlines they move.

### Stage 5: the document

`parse_blocks_located s` runs each piece from line 0 and shifts it into
place with `Shift.of_blocks`.  Two lemmas:

- `dn_node` commutes with shifting a node and its windows;
- the fold `cut` keeps `stored_ok` at `pend_count`, and restarts from an
  idle state, which holds it trivially.

Then the theorem, and the coverage rows M2 and M3 drop their gap note.

## Pitfalls

- **Ordering.**  `para_inlines_spans` needs the lines in strictly
  increasing order.  `lix` is the line's index in its piece and the
  accumulator conses, so the invariant carries `k < i` for the next
  line; a lazy line and a container's line both store at `lix`, once.
- **The last line is stripped.**  `para_windows` reads the last stored
  line through `strip_trailing_ws`, which is a prefix of it, and starts
  it at the unstripped length.  `windows_embed` asks for a prefix, so
  this is the same case as any other line.
- **Cells.**  The row part is computed by a second scan
  (`row_cells_trace`) over `drop_leading_ws l`, while the cells come from
  `classify`.  That the two agree is the one fact here that is not about
  suffixes, and the probe will say whether it holds.  If the proof is
  long, split cells into their own plan and state the theorem for blocks
  without tables first.
- **Fuel.**  State the stage 3 and 4 lemmas over `step_fuel n off`, with
  the line a suffix of `L_lix` whatever `off` is; `off` is a column and
  plays no part here.
- **Iterate with rocq-mcp,** not edit-and-rebuild; `force_restart` after
  a rebuild.
