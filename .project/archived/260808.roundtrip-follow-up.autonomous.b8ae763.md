# Canonical roundtrip: potential follow-up

Commit `b8ae763` completes canonical flat bullet-list roundtrips. Tight and
loose lists now pass through `parse_cblock`, `roundtrip_blocks`, and
`roundtrip_doc`; lists inside quotes are covered too. The former global
`no_nested_list` exclusion is gone.

## Refactoring worth doing

`Roundtrip.v` is now large, but its proof is layered rather than one monolith.
Refactor conservatively, after first writing a section map. The natural seams
are:

1. generic line, separator, and parser-run lemmas;
2. padded block parsing (`parse_cblock_pad` and its support);
3. canonical list-item and list-state lemmas;
4. whole-block and document roundtrip theorems plus examples.

A file split is reasonable only if those layers can be given small, acyclic
interfaces. In particular, do not split the list proof merely by moving a
contiguous range: its dependencies on padded parsing and canonical rendering
should be made explicit first. Prefer small helper records or named state
invariants where long argument lists currently repeat the same `PList` facts.
Keep the concrete tight/loose examples near the public theorem as regression
witnesses.

One small cleanup should come first: update or archive the 2026-08-07 list
handover, whose “one piece left” and `no_nested_list` sections are now stale.

## Proof-quality checks

- Add focused boolean tests for `no_adjacent_lists`, especially three-block
  sequences. The old alias pattern accidentally checked pairs 1–2, 3–4, and
  so on; the corrected definition slides by one block.
- Review repeated boundary arguments in `parse_cblock` and `parse_sep` for a
  shared lemma that exposes the first block, the remaining canonical sequence,
  and the non-list boundary fact together.
- Keep using RocqMCP for local state inspection, followed by a full Dune build.
  The useful trust boundary remains the compiled source, not a successful
  isolated tactic experiment.
- Avoid shortening the proofs through aggressive automation until the state
  invariants have stable names. The current explicit transitions are verbose
  but reviewable.

## Genuine feature extensions

These are separate projects, not refactors:

- **Nested lists inside list items.** `list_content_safe` still rejects them.
  Supporting them needs an indent-shift invariant showing that adding the
  outer item's whitespace shifts all relevant `PList` comparisons uniformly.
- **Code fences inside list items.** These remain unsafe because verbatim fence
  content retains the list indentation. This should be solved together with
  the related indented-fence-in-quote behavior, using an explicit ambient
  indentation model or a proven dedent operation.
- **Adjacent top-level lists.** `cblocks_ok` rejects them because the canonical
  rendering does not preserve a distinct list boundary. Supporting them needs
  a renderer or AST policy that makes that boundary observable; weakening the
  predicate alone would make the roundtrip statement false.

Suggested order: document the current file structure, add the adjacency
regressions, extract only clearly reusable boundary invariants, then choose one
of the three feature extensions as a separately scoped proof project.
