## The headline results

Six of the 120 theorems carry the development. Each answers `Print
Assumptions` with *Closed under the global context*: no axioms, no
admitted lemmas.

### `roundtrip_blocks` (Roundtrip.v:1886)

```coq
forall cbs, cblocks_ok cbs = true ->
  parse_blocks (render_djot (blocks_of_cblocks cbs)) = blocks_of_cblocks cbs.
```

The centre. Render a canonical document, parse it back, get the same
value. Exact equality, not equivalence modulo a normalization relation.
The `cblocks_ok` hypothesis is the honest part: it names which ASTs have
a canonical source spelling at all.

### `roundtrip_doc` (Roundtrip.v:2323)

```coq
forall cbs, cblocks_ok cbs = true -> pristine (blocks_of_cblocks cbs) = true ->
  undo_pass (doc_blocks (parse_doc (render_djot (blocks_of_cblocks cbs))))
  = blocks_of_cblocks cbs.
```

The same statement at the parser's real entry point, with the
whole-document pass (section nesting, id assignment, footnote collection)
run and then undone. `pristine` is the second hypothesis because a block
already carrying an explicit id is not one the pass can be undone
through.

### `wf_parse` (Wf.v:3073)

```coq
forall s, wf_blocks (parse_blocks s) = true.
```

No hypothesis at all: any string parses to a well-formed tree. Most of
`Wf.v`'s 4,434 lines are what it costs to say that about arbitrary input.

### `block_incremental_holds` (Invariants.v:83)

```coq
forall T K, block_incremental T K.
```

Three properties bundled, for every table and every block config:
parsing is prefix-deterministic, later lines cannot revise committed
blocks, and the explicit state suffices to continue. The parser carries
no hidden history. Proved by handing over `prefix_determinism`,
`no_future_line_dependence` and `prefix_state_suffices`.

### `pass_erase` (Document.v:2394)

```coq
forall bs, pristine bs = true -> undo_pass (doc_blocks (doc_pass bs)) = bs.
```

The whole-document pass is reversible on pristine input. This is what
`roundtrip_doc` stands on, and the reason the document layer can be added
without disturbing the block roundtrip underneath it.

### `rename_canonical_local` (Site.v:955)

Renaming a note confines the canonicity re-check to the renamed note and
the notes that link to it. The furthest-out result: a directory of notes
routed to URLs, with the link convention a parameter rather than a fixed
choice.

## What holds up the roundtrip

`roundtrip_blocks` is ten lines of proof script. The weight sits under it
in three separable piles.

```
                    roundtrip_doc
                     /         \
       roundtrip_blocks      pass_erase
        /      |      \
       /       |       \
  Render.v  uniformity  Step.v metatheory
  cblock    chain       step_fuel_shift
  cb_ok     quote/div/  step_fuel_pad
  cb_lines  attr/list/
            ck
```

- **The canonical fragment** (`Render.v`) says which ASTs have a source
  spelling. A gap here means an AST you cannot write down.
- **The uniformity chain** says container contents parse by the same
  rules as top-level input. A gap here means a container that reads
  differently inside than out.
- **The `Step.v` metatheory** says padding a line and shifting the offset
  are the same descent. A gap here is the one that would hurt, because
  every descent goes through it. This is the standing constraint on what
  any new `pstate` constructor may record; see
  `.project/project-engineering-lessons.md`.

## The boundary

What the development does not claim. Stated in `Overview.v` rather than
left to be inferred.

- **HTML fidelity.** `Html.v` is checked differentially against the
  oracles, not proved, and is not the subject of the roundtrip theorem.
- **The oracles.** `djot.js` and `djoths` are executable references.
  Neither is verified. Disagreements are logged in
  `.project/oracle-disagreements.md` rather than resolved by fiat.
- **Source positions and CLI behaviour.** Carried for fidelity with the
  oracles; nothing renders or proves them.
- **The converse of `wf_parse`.** Not merely unproved.
  `wf_complete_false` is a theorem that it is false. Well-formedness is a
  sound over-approximation of the parser's image, not an exact
  characterization, and the development records that rather than
  weakening the predicate to make it look tight.
