# Single-line headings as a block capability

## Problem and boundary

Djot keeps an ATX heading open across a same-level marker or an ordinary text
line.  Thus `# a` / `# b` and `# a` / `b` each become one multiline heading.
The Markdown-like profile should instead close an ATX heading after its first
source line.  Djot's default remains unchanged.

Add one boolean to `bconfig`: whether an open ATX heading may consume another
line.  This belongs beside paragraph interruption, underlining, and tables:
it changes one answer in the block state machine and has no inline effect.

## Parser and canonical view

When continuation is enabled, retain the existing `PHeading` transition.
When disabled, close the heading and reprocess the current line from the idle
state.  Reprocessing uses the existing single fuel decrement, so a quote or
list on that line still opens through the ordinary recursive path and the
incremental invariants keep their statements.

`heading_ok` admits multiple canonical source lines only when continuation is
enabled.  With it disabled, a canonical heading must have exactly one line;
otherwise rendering one AST heading would parse as several blocks.  The AST
itself does not change.

## Obligations and witnesses

- `with_heading_continuation` preserves block incrementality and the unrelated
  lone-dash prefix invariant.
- Heading transition equations expose the capability premise only where a
  line continues an already-open heading.
- Roundtrip uses the `heading_ok` singleton fact when continuation is off.
- Djot witnesses retain lazy and same-level continuation.
- Markdown witnesses show `# a` / `# b` as two headings and `# a` / `b` as a
  heading followed by a paragraph.
