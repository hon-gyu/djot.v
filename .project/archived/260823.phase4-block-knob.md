# The block-layer knob: a paragraph a list marker may interrupt

Phase 4's precondition, run against the one knob
[[beyond-djot]] names first: *in djot, a sublist must always be preceded
by a blank line. I'd like to make this optional under a configuration
flag.*

The audit is not a document. It is a spike: the knob was added as a class
parameter, the development was made to compile over it, and the corpus,
the generated corpus and the roundtrip were re-run at djot's instance.
Everything below is measured.

## 0. The baseline, pinned first

Per [[extension-decisions]] discipline 1, what djot does today
(djot.js v0.3.2):

| input | djot today |
| ----- | ---------- |
| `- a` / `- b` | two items |
| `- a` / `  - b` | one item, whose text is `a` / `- b` |
| `- a` / blank / `  - b` | one item containing a nested list |
| `p` / `- b` | one paragraph |
| `The civil war ended in` / `1865. And this should not start a list.` | one paragraph |

The rule being relaxed is therefore **not** "a list needs a blank line
before it". A sibling marker already interrupts with no blank, because
the list container's own continuation rule sees the line before the
paragraph does. What swallows the indented marker is one arm of one
branch, `Step.v`'s `PPara (c :: cur')`:

```coq
| _ => ([], PPara (drop_leading_ws l :: c :: cur'))   (* paragraphs never interrupt *)
```

## 1. Where the knob goes, decided by a theorem rather than by taste

Two placements are possible and they are not equivalent.

**In `PList`'s indented-content arm**: only a sublist changes, top-level
prose is untouched. This is what the ask says literally, and it is
**wrong**. `list_uniformity`'s conclusion is
`parse_lines (snd it) (PPara [])` -- an item's lines parse as they would
at top level. A marker that means one thing inside an item and another
outside falsifies it. The rule also lands in the parser's most
theorem-dense branch.

**In `PPara`**: a list marker closes any open paragraph, wherever it
sits. Uniformity survives untouched because the rule never mentions the
enclosing container. This is the placement, and the answer to the
question [[beyond-djot]] left open ("how does the list-uniformity hold
under this new rule?") is: *it holds exactly when the rule is stated
without reference to the container*.

## 2. The knob's type is what keeps it from going viral

```coq
Class bconfig : Type := BConfig {
  bmarker_interrupts : list lstyle -> string -> option task_status -> string -> bool
}.

Definition binterrupt `{bconfig} (k : line_kind) : bool :=
  match k with
  | KList sty core chk rest => bmarker_interrupts sty core chk rest
  | _ => false
  end.
```

The first spelling tried was `binterrupt : line_kind -> bool`, and it
cost immediately: `parse_lines_text` could no longer discharge
"a text line does not interrupt", because for an arbitrary table it
might. Taking the marker's fields as the knob's *arguments* puts that
fact in the type, so every non-list kind answers `false` definitionally
and no class law is needed to say so. This is
[[project-engineering-lessons#Prefer the stronger precondition when the
weaker one is viral]] applied to a signature rather than to a hypothesis.

Widening the knob from a plain `bool` to this predicate afterwards cost
**zero** further proof edits, which is the check that the restriction is
carrying the weight.

## 4. What the knob changes, measured on the corpus

Scanned all 291 fenced cases in `djot.js/test/*.test` for a paragraph
with an interior line that starts with a list marker -- exactly the
documents the knob re-reads. **Five**, all in `lists.test`:

- cases 2, 6, 11, 12: the sublist shape, which is what the ask wants.
- case 33:

```
The civil war ended in
1865. And this should not start a list.
```

That case is djot's own regression test for the accidental-list problem,
sitting in the corpus with its intent written in the input. A knob that
lets *any* marker interrupt turns it into a paragraph plus an ordered
list starting at 1865, which was confirmed by computation, not predicted.

So the broad rule costs exactly one corpus case, and it is the one the
design rationale is about.

## 5. Two instances, and the one worth shipping

```coq
Definition sublist_any : bconfig := BConfig (fun _ _ _ _ => true).

Definition sublist_safe : bconfig :=
  BConfig (fun _ core _ _ =>
            match core with
            | EmptyString => true            (* a bullet *)
            | _ => String.eqb core "1"       (* or the numeral 1 *)
            end).
```

Measured:

| input | djot | `sublist_any` | `sublist_safe` |
| ----- | ---- | ------------- | -------------- |
| `- a` / `  - b` | text | nested list | nested list |
| `p` / `1. one` | text | list | list |
| civil war / `1865.` | text | **list (bad)** | text |

`sublist_safe` is conservative on all 291 corpus cases except the four
that are the ask, and it is a *line-local* test on the marker's own
numeral -- no context, no state, nothing that could reintroduce
backtracking. This is Phase 5's stated worked target ("paragraph
interruption by unambiguous-marker constructs only, provably immune to
the accidental-list problem") reached at the probe stage, because the
knob's type made the restriction expressible.

`sublist_safe` ships as `sublist_bconfig` in `Step.v`, pinned in
`check/Sublist.v` and argued in [[extension-decisions]] `E2`.

Roman `i.` does not interrupt under this rule, since only `1` is
admitted. Whether that should be widened is open and stays open there.

## 6. The roundtrip pays nothing, and the reason is the escaper

The predicted cost was that `cb_ok` would shrink: a paragraph whose
interior line reads `- b` cannot round-trip once markers interrupt. It
does not shrink, because the renderer **already escapes** a
line-initial marker:

```coq
Compute map ci_line (map cline ["a"; "- b"]).   (* = ["a"; "\- b"] *)
```

and `\- b` classifies as text at every instance. So the new `para_ok`
clause is discharged by escaping that predates the knob, and no canonical
document leaves the fragment. The clause is not vacuous -- `para_ok`
quantifies over arbitrary strings, and it rejects the unescaped spelling:

| `para_ok` at `sublist_safe` | |
| ------------------------- | -- |
| `["a"; "- b"]` | false |
| `["a"; "\- b"]` | true |
| `["a"; "1865. x"]` | true |
| `["a"; "1. x"]` | false |

This is the good case of
[[project-engineering-lessons#Probe the equations a new pass must
preserve]]: a change is free when it is the identity on the inputs the
existing theorems quantify over, and here the escaper had already made it
so.
