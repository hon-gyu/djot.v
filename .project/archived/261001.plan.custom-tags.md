# Plan: custom tag names (jgm/djot#240)

Source: <https://github.com/jgm/djot/issues/240>, "Proposal: explicit
syntax for custom tags" (matklad, 2023-08-20, open, no consensus). No
djot implementation has it, so the discipline in [[extension-decisions]]
applies rather than [[project-engineering-lessons#Ask djot.js]].

## The proposal, in one paragraph

A div and a span each gain one **name**, separate from their classes.
`::: details` sets the name of a div where today it adds a class, and a
new inline spelling `:kbd[Ctrl+C]` sets the name of a span. The HTML
renderer uses the name as the element name. The thread's objections are
about portability (a name means nothing to a LaTeX renderer), about
pandoc's AST having no such field, and about `:tag[` looking like an
unfinished symbol. Alternatives floated there: `!tag[...]`, `[x]{:tag}`,
`[x]{tag}`, and block-only (dereuromark, from djot-php's experience).

## Goal

Both halves as profile capabilities, off in `djot_profile` and
`markdown_like_profile`, with the standing theorems (roundtrip,
well-formedness, uniformity, incrementality, single-pass scanning)
holding at every setting. Syntax only, as for wikilinks and callouts:
the parser records the name that was written, and what a name means is
the consumer's.

non-orthogonal, so it has to be understood first.

## Compatibility (discipline 4)

Both halves are non-conservative.

- Block: every document with `::: word` changes, from a class to a
  name. Loud in HTML (`<div class="word">` becomes `<word>`).
- Inline: the divergent set is the documents containing `:` then one or
  more symbol characters then `[`. The first four baseline rows move.
  Prose such as `note:see[this](url)` is in the set, which is the cost
  of the leading-colon spelling.

Step 0 counts both shapes in the 291 corpus cases.

## Decisions

Made by the agent on 2026-10-02, without human review. Each carries a
reason that is not taste (discipline 3) and the condition that would
reopen it. They become settled entries in `extension-decisions.md` only
once an `Example` pins them (discipline 2).

| | decision |
| --- | --- |
| D1 | the name is a field on `Div` and `Span`; empty means unnamed |
| D2 | the inline spelling is `:name[...]` |
| D3 | `]` closes a named bracket at once; a following `(u)` or `[ref]` is text |
| D4 | each name is recorded as written; the two alphabets are not unified; an empty inline name is not a name; no length bound |
| D5 | `::: div` and `:span[x]` are recorded as written, not folded into the unnamed node |
| D6 | HTML uses the name only for elements with ordinary content, and otherwise falls back to `div` / `span` with the name in `data-tag` |

**D1. A field: `Div (name : string) bs`, `Span (name : string) ils`.**

| option | cost | verdict |
| --- | --- | --- |
| a field, empty meaning unnamed | every match gains a binder, no theorem gains a case | chosen |
| new constructors `Element` / `InlineElement` | each standing theorem gains a case; `CDiv`'s proofs are duplicated | rejected |
| a reserved attribute key | none in the AST | rejected: a user can write the same key, so the canonical view cannot tell them apart |

Reason: a named div parses, nests, closes and renders exactly as a div
does, so a second constructor would restate every div and span proof
for a node that differs in one string. `PDiv` already carries the word,
and E1's `marked` flag is the precedent for "a field, not a
constructor". A string and not an `option`, so that there is one
unnamed value and `div_block`'s existing empty-word test carries over.

Reopens if: the step 2 census finds the binder breaks proofs that
compute through `Div` / `Span` (the comment on `div_block` says the
classless case is kept `mk`-wrapped so that proofs compute through it).
Then the constructors are the fallback.

**D2. `:name[...]`, as proposed.**

Reason: `ISymbol` already accumulates exactly this buffer and decides
at the next byte, so the opener needs no lookahead, no new accumulating
state, and no second reading carried alongside
([[no-backtracking]]). `!name[` has no such state to reuse and collides
with the image opener's `IBang`. `[x]{:name}` and `[x]{name}` put the
name in the attribute parser, where it could be written twice on one
node, and the second closes off djot#257 (bare words as flag
attributes).

Reopens if: the corpus count in step 0 shows `:word[` is common in
existing prose. Then the inline half is dropped and the plan ships
block-only (step 4), which is dereuromark's narrowing in the thread.

**D3. `]` closes a named bracket at once.**

Reason: an ordinary `]` waits one byte in `IClosed` because the bracket
is nothing without what follows. A named bracket is already a span, so
waiting would let `:kbd[a](u)` be read as a link and lose the name, or
give `Link` a name too. Closing at once keeps "one source, one node".
A following `{...}` attaches attributes, as it does to any inline.

Consequence to pin: `:kbd[a](u)` is a named span followed by the text
`(u)`.

**D4. Record as written; do not unify the alphabets.**

The block word is `is_class_char` and the inline alias is
`symbol_char`. Reason for not unifying: `classify` is
profile-independent by design, so narrowing the block word would
change which lines are div openers in the djot profile too. Whether a
name is usable is the consumer's question (D6 answers it for HTML).

An empty inline name is not a name: `:[a]` keeps today's reading. This
is forced, since the unnamed span is the empty name (D1) and its
spelling is `[a]{...}`.

No length bound. jgm asked for one to keep parsing fast; this scanner
accumulates the alias in one pass either way, so a bound would be a
rule with no theorem behind it.

**D5. `::: div` has the name `div`.**

Reason: folding it into the unnamed node gives one AST two spellings,
and the canonical view would need a special case to stay injective.
Recorded as written, `::: div` and `:::` are different nodes that
happen to render to the same HTML. This departs from the proposal,
which names the bare forms `div` and `span`.

**D6. HTML uses the name only where its escaping is right.**

The name is the element name when it is ASCII letters, digits and
hyphens starting with a letter, and is not a void element (`br`, `img`,
`input`, `meta`, ...), a raw-text or escapable raw-text element
(`script`, `style`, `textarea`, `title`), or one of the legacy
elements that switch the tokenizer (`xmp`, `iframe`, `noembed`,
`noframes`, `plaintext`, `noscript`). Otherwise the element is `div` /
`span` and the name goes in a `data-tag` attribute.

Reason: correctness, not caution. `Html.v` escapes for ordinary
content; inside `<script>` that escaping is not what the browser
undoes, so the output would not denote the AST. `:script[alert(1)]` is
the witness. A void element cannot hold the children the node has.

`data-tag` and not a class, because writing the name as a class
recreates the conflation of name and class that the extension exists
to remove.

Reopens if: a consumer needs a wider or narrower set. Then the list
becomes a renderer parameter; the parser is unaffected.

## Out of scope

Names on verbatim and code blocks (jgm's ```` ``` tikz ```` and
`` :kbd`x` ``), a tag dictionary for non-English aliases, bodyless
`:meta{...}`, filters, and any renderer other than HTML.

7. **HTML.** D6 in `Html.v`: `Div` and `Span` cases, plus the name

## Pitfalls

- A stale rocq-mcp session answers for the old AST after step 3; pass
  `force_restart`.
- The field on `Span` (D1) touches the delimiter table's `dnode`;
  `dstyle` itself does not change.
- `ISymbol` holds a shadow text state (`sh'`). The named-bracket branch
  must discard it, not resume it, or the colon is emitted twice.
- A name is not a symbol: `:kbd:[a]` stays a symbol followed by a
  bracket at every setting.
- `ci_inlines` takes no table argument today; it must still not after
  step 5.
