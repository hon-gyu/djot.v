# A code fence records the column it opened at

## The gap

`PFence` stored its content lines verbatim and recorded no column, so a
fence opened inside anything that indents its contents kept that
indentation in the block:

```
  ``` python
  if true:
    x = 3
  ```
```

gave `<pre><code class="language-python">  if true:` where both oracles
give `if true:`.  The same shape inside a list item and inside a
footnote definition failed the same way; `code_blocks.test:21` and
`footnotes.test:1` were the two corpus cases, and the second was the
last gallina failure in `footnotes.test`.

This was a *known* gap rather than a surprise.  The `PList` branch of
`step_fuel` says so in as many words: the line "is passed down
unchanged -- every recognizer already skips leading whitespace, so block
structure is right; what the extra indent still costs is inline and
verbatim text".  Block structure was right; verbatim text was the half
that was still owed.

## What djot.js does

`block.ts:1081-1086`.  A container whose `content` is
`ContentType.Text` -- and `code_block` is the only one -- contributes a
line starting not at the first nonspace but at
`pos - (indent - tip.indent)`, where `tip.indent` was recorded as
`this.indent` when the fence opened (`block.ts:710`).  So the container
removes exactly its own column from each line: a line indented less than
the fence keeps nothing of its indentation, one indented more keeps the
difference.  Confirmed against the oracle on a shorter line, a tab, and
a blank line, all three of which the reading above gets right.

## The change

`PFence f ind acc`, with `ind` the *absolute* column `off + indent_of l`
the border sat at, exactly as `PAttr`, `PRef`, `PFoot` and `PList` record
theirs.  A content line is stored as `drop_ws_upto (ind - off) l`.

The shape of the work was predicted in full by
[[project-engineering-lessons#Probe the definitions a theorem already
constrains, too]], which is the entry written when `PAttr` learned the
same lesson.  Recording a column means `open_kind` cannot build the
state, because `open_kind` never sees the offset: so `open_fence` came
out of `open_kind`, `direct_open` lost `KFence`, the four call sites that
opened through `open_kind` grew a `KFence` arm, `step_fence_open` and
`step_list_fence_close` were written to replace the `step_idle` and
`step_list_close` instances that `direct_open` no longer supplies, and
`pad_state` moves the new column.  Nothing else in the state changed.

`drop_ws_upto n s` drops a leading whitespace run of at most `n`
characters.  Written that way rather than as `min (indent_of s) n` it
needs no side condition, and its one lemma
(`drop_ws_upto_ws_prefix`) is the statement that a pad of `n` blanks and
`n` more columns to strip cancel.

**`step_fuel_shift` gains the fence and `step_fuel_pad` does not.**  The
shift moves the recorded column along with the offset, so the difference
`ind - off` a content line is measured against is invariant and the
fence branch goes through.  The pad lemma carries the *same* state on
both sides, so the padded side strips a column recorded before the pad
existed and keeps `String.length p` characters too many.  The first step
left `pad_safe` excluding `PFence` for that new reason rather than for
verbatim storage; the second step below turns the exclusion into a side
condition, which is what the whole change was for.

## The exclusion it was owed, and the predicate that split

Landed as a second step, and it is the payoff the first one was for.

The canonical fragment excluded a code block anywhere inside a list item
(`Generate.no_fence`, guarding `item_ok`'s `run_pad_safe` conjunct),
because fence content was verbatim and a pad in front of it was not a
shift.  With the column recorded, `step_fuel_pad`'s fence branch is true
under one side condition -- the fence must sit at or right of where the
padded line starts, since both sides of that equation carry the same
state.  `fence_cols_ok off st` is that condition, and it is free at both
call sites: `pad_state` has already moved every column by the pad's own
width (`fence_cols_ok_pad`), and column zero is left of everything.

**What actually cost something was `step_blank_finish`, not the pad.**
`pad_safe` was one predicate doing two jobs, and its own comment said so:
"if a third state needs one and not the other, that predicate should
split".  It has.  `pad_safe` is now "no attribute spec is open", asked of
*every* state a run passes through; `blank_safe` is "a blank line closes
what this has open", which excludes a fence and a spec and is asked only
of the state a run *ends* in.  `run_safe` (renamed from `run_pad_safe`,
which no longer describes it) carries one in its cons case and the other
in its nil case.  That is the whole of why an item may now contain a code
block: it may pass through an open fence, it may not end inside one --
and no canonical rendering does.

Measured.  `Generate.uniformity_applies` still computes `true` with the
pool no longer filtered, which is the check that the hypothesis is
satisfiable rather than merely weaker.  `cb_ok` now accepts
`CList [[CCode "" ["x"]]]` and the same nested, pinned as three
`Example`s.  The generated corpus grows from 3094 documents to **3380**
and exact matches from 3067 to **3350**; the 30 mismatches are all
`- :::`, the div-in-a-tight-item `<p>` family already logged, up from 27
only because the enumeration is larger.  `accepted_counts` goes from
`(150, 1870, 22450)` to `(160, 2020, 24220)`, and `make probe`'s
conditional pad probe from 589 passes / 186 skips to 651 / 124 with no
failures.

## Appendix: the design question the two steps turned on

A recorded column can be spelled absolutely (`off + indent_of l`) or
relatively (`indent_of l`, with the offset implied), and the two are
extensionally equal on every input the quote and list prefixes can
produce.  They are *not* equal as definitions, and the two pad theorems
pick different winners: the relative spelling satisfies the composite
pad-and-shift statement exactly, with no side condition at all, while the
absolute one needs `fence_cols_ok`.  The absolute spelling wins anyway,
because `step_fuel_shift` quantifies over all states and is false for the
relative one -- and a hypothesis on `step_fuel_shift` would travel
everywhere, which is
[[project-engineering-lessons#Prefer the stronger precondition when the
weaker one is viral]].  So the side condition went on the lemma with two
call sites rather than on the lemma with twenty.
