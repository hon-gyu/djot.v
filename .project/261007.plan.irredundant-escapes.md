# Plan: a renderer with no redundant escape

## Goal

A second theorem about `Render.render_djot`, next to the round trip:

```
cblocks_ok cbs = true ->
forall i, byte i of (render_djot cbs) is a backslash ->
  parse_blocks (delete i (render_djot cbs)) <> blocks_of_cblocks cbs
```

and the same for each braced span written bare.  The statement needs no
notion of "an escape": it holds of every backslash byte, since deleting
one in a code block or in `\\` changes the content.

The round trip stays as it is.  It is a statement about the parser, and
any renderer satisfies it.  This one is about the renderer.

This supersedes steps 2 to 5 of
`261004.plan.canonical-renderer-relaxation.md`.  Its step 1 is done.

## What is measured today

`test/escapes.ml` renders `Generate.escape_accepted` (1863 documents),
deletes each backslash and each brace pair in turn, and counts the
deletions that leave the parse unchanged.  The count is pinned and may
only go down.

| state                                           | redundant |
| ----------------------------------------------- | --------- |
| destinations escape only `\`, `(`, `)`, `` ` `` | 1722      |
| a delimiter character between spaces goes bare  | 1668      |

Before the destination change the count was about 200 higher; it was
taken with a cruder deduplication (2031 against 1815) and is not
comparable to the rows above.

Nearly all of the 1668 are lone openers: `a\[b`, `a\_b`, `a\{b`, `a\$b`,
`a\<b`, `\:a`.  Each is redundant because nothing later completes it.
No rule over neighbouring bytes can know that, so the remaining
context-free rules are worth perhaps a tenth of the count.

## The rule

Leave every opener bare.  Escape the byte that would complete a
construct: the `_` that would close, the `]` before `(`, the third
period, the `>` of an autolink.  An opener nothing completes decays to
text in the scanner, merged with its neighbours (`oapp`, `osnoc`), which
is the `Str` the tree holds.

The renderer decides by running the scanner.  Writing a `Str`, it holds
the scanner state `st` reached on everything written so far, and for
each byte `c`:

```
bare c  iff  view (istep c st) = view st + c          (harmless)
         and view (scan `\\` (istep c st))
             = view (istep c st) + `\`               (escapes still decode)
```

where `view` is `ifinish`: what the scan would yield if the line ended
here.  Otherwise it writes `\c`.

The second line rejects a state that reads its input raw.  A footnote
label after `[^`, a comment after `{%` and an autolink region after `<`
keep a backslash as two bytes, so an escape written later would not
decode.

Two characters need more than this:

- `\` is bare only before a letter or digit.  Its completer is the next
  byte, and a space or a line end after it cannot be escaped.
- The last byte of a run followed by another inline is tested with that
  inline's first byte appended, so that `!` before a link is escaped.

### Prototype result

A throwaway OCaml prototype of this rule over the extracted scanner (not
kept) rendered every single-`Str` line of up to 4 characters over
letters, space and all ASCII punctuation: 1,297,032 strings.

- Wrong parses: 0.
- Without the second line of the rule: 9 wrong at length 3, all after
  `[^` or `{%`.

Redundant escapes left, by character: `<` (the guard rejects every
autolink candidate), `\` (the guard does not apply to it as written),
`%` and `^` (the guard rejects `{%` and `[^` even at the end of a line),
and about 30 each of `_`, `*`, `~`.  These are the known gaps of the
rule as stated, to be closed one by one against the check.

The prototype covers one `Str` on one line.  It says nothing yet about
real constructs around the text, lines after the first, or blocks.

## What the rule does not cover by itself

A bare opener is safe from later text, because the completer is tested.
It is not automatically safe from a later real construct, whose bytes
cannot be escaped:

- A real `]` closes the innermost bracket.  A literal `[` inside a
  link's text would be that bracket.  So inside real brackets a literal
  `[` is escaped.  Outside them it is safe: a bracket frame is not a
  barrier (`fr_barrier`), so a braced closer walks past it.
- A real braced closer `_}` matches marked frames only (`dmatch`), and
  abandons unmarked frames above it.  Safe.
- An unmarked closer inside a real span could reach past the span's
  frame to a bare opener outside it.  The first test catches this, since
  the view changes.
- A paragraph is one scan (`para_inlines`).  A bare opener on one line
  can be closed on the next, so the state is carried across the lines of
  a paragraph, through `ibreak`.
- A line's first byte is a block question (`- `, `# `, `> `, `: `, a
  fence, a table row).  The scanner state does not answer it.  Today the
  first byte of a run is always escaped.  The exact rule asks
  `Line.classify` of the line as written.

Bare spans (`_a_` for `{_a_}`) are the last step.  `Readable.bare_ok` is
the candidate condition.  Once spans are bare, an unmarked frame is no
longer always a literal, and the invariant below has to say which is
which.

## Proof shape

Today `iscan_escape_from` says a `Str` scans from `IText false txt prev
o` to `IText false (txt ++ s) _ o` for every `o`.  Text never touches
the stack, and every construct lemma is stated over an arbitrary stack
below it (`iscan_cis_scope`).  With bare openers that is false: text
pushes frames.

The replacement is a relation between the state the new rendering
reaches and the state the fully escaped rendering reaches:

```
R st st'  :=  mode and previous byte agree,
              and settle (flush st) = settle (flush st')
```

`settle` abandons every literal frame into the scope below it, the way
`oclose_go` and `bclose_go` already do when they pass one:
`oapp (oapp (fr_out f) [OIn (fr_lit f)]) below`.  While real spans are
braced, a literal delimiter frame is exactly an unmarked `FKDelim`, so
`settle` is a function of the stack and needs no tags.  Literal brackets
are not distinguishable by kind; either `R` carries the list of literal
frames explicitly, or brackets are handled in a later phase.

Obligations:

1. **Text.**  A byte the rule writes bare preserves `R` against the
   escaped pair.  Mostly by the rule's own test, once `view` is related
   to `settle`.
2. **Real constructs.**  Each token a construct writes (`{_`, `_}`, `[`,
   `](`, a verbatim, an autolink) preserves `R`.  This is the bulk: every
   lemma in `InlineInvert.v` from `iscan_marked_open` to `iscan_cis_tag`
   is restated up to `settle`.
3. **Finish.**  `R st st'` implies `ifinish st = ifinish st'`.  `ofinish`
   flattens the whole stack through the same `oapp`, so this should be
   close to the definition.
4. **Lines.**  `para_inlines_cons2_closed` assumes each line leaves the
   scan closed.  It becomes a statement up to `R`.
5. **Irredundancy.**  For each escape written, the rule's test failed,
   so the bare byte changes the view.  The theorem needs that a changed
   view at that point is a changed parse at the end, which is a
   monotonicity fact about the scanner: a node emitted or a frame closed
   is not undone later.

Obligation 5 is the least understood.  A frame closed by a bare byte
could in principle be abandoned later and decay to the same text.  The
check will show whether that happens before any proof is attempted.

## Phases

Each phase lands a renderer change with its round trip proved, and
lowers the pinned count.  Irredundancy is proved at the end, when the
count is zero.

1. **Renderer as a definition, unproved, beside the current one.**
   `ci_src` threads the scanner state; `Str` uses the rule.  Run the
   round-trip pools and the escape check against it.  This validates the
   rule on real constructs, lines and blocks, which the prototype did
   not reach.  No proof work.  If it fails here the design changes
   cheaply.
2. **`settle`, `R`, and obligation 3.**  Small, and it fixes the
   vocabulary for everything after.
3. **Delimiter characters.**  Literal frames are unmarked delimiter
   frames only.  Obligations 1, 2 and 4 for that case.  Brackets, braces,
   `<`, `$`, `:` stay escaped as today.
4. **Waiting characters with no frame**: `{`, `}`, `$`, `:`, `<`, `\`.
   These leave the stack alone, so they fit the phase 3 relation.
5. **Brackets.**  Needs the tagged form of `R`, or a proof that the
   enclosing-bracket flag is enough.
6. **Line starts.**  Replace "first byte of a run is escaped" by the
   classification of the line as written.
7. **Bare spans.**
8. **The theorem**, obligation 5.

Phases 3 and 4 remove most of the count and leave brackets and bare
spans, which are the two places the design is still open.

## Costs and risks

- `InlineInvert.v` is 4200 lines and most of it is obligation 2.  Expect
  it to be largely rewritten over phases 3 to 5.
- The renderer becomes a function of the scanner.  `InlineView.v` cannot
  import `InlineScan.v` today (the dependency runs the other way), so
  the state-carrying part of the renderer moves to a file after the
  scanner, and `Render.v` uses it from there.
- Output depends on context.  An edit in one part of a paragraph can add
  or remove an escape elsewhere in it.
- The canonical view excludes some shapes today because the escaped
  spelling could not express them.  A relaxation that shrinks the
  accepted counts in `test/roundtrip.ml` is a regression even if the
  theorems close.
- Every statement is under `Context {T : dtable}`.  The rule is stated
  through the scanner, so it follows the table in force without a case
  per row.
