# Plan: a renderer with no redundant escape

## Goal

A second theorem about `Render.render_djot`, next to the round trip:

```
cblocks_ok cbs = true ->
forall i, byte i of (render_djot cbs) is a backslash ->
  parse_blocks (delete i (render_djot cbs)) <> blocks_of_cblocks cbs
```

and the same for each braced span written bare.  The statement needs no
notion of "an escape": it holds of every backslash byte, since deleting
one in a code block or in `\\` changes the content.

The round trip stays as it is.  It is a statement about the parser, and
any renderer satisfies it.  This one is about the renderer.

This supersedes steps 2 to 5 of
[[261004.plan.canonical-renderer-relaxation]] (archived).  Its step 1
is done.

## What is measured today

`test/escapes.ml` renders `Generate.escape_accepted` (1863 documents),
deletes each backslash and each brace pair in turn, and counts the
deletions that leave the parse unchanged.  The count is pinned and may
only go down.

| state                                           | redundant |
| ----------------------------------------------- | --------- |
| destinations escape only `\`, `(`, `)`, `` ` `` | 1722      |
| a delimiter character between spaces goes bare  | 1668      |
| `RenderScan.v` (phase 1, 2026-10-15)            | 539       |
| `Irredundant.v` (2026-10-16, proved)            | 0         |

Before the destination change the count was about 200 higher; it was
taken with a cruder deduplication (2031 against 1815) and is not
comparable to the rows above.

Nearly all of the 1668 are lone openers: `a\[b`, `a\_b`, `a\{b`, `a\$b`,
`a\<b`, `\:a`.  Each is redundant because nothing later completes it.
No rule over neighbouring bytes can know that, so the remaining
context-free rules are worth perhaps a tenth of the count.

## The specification

`Irredundant.irredundant_spec` starts from `render_djot` and deletes a
backslash, or a `{` and a later `}` with no empty line between them,
whenever what is left parses as `render_djot`'s output does, until no
such deletion is left (`shrink`).  Its theorems hold by construction:

| Theorem | Statement |
| --- | --- |
| `spec_roundtrip` | for `cblocks_ok cbs`, it parses back to `blocks_of_cblocks cbs` |
| `spec_backslash` | deleting any backslash of it changes its parse |
| `spec_braces` | deleting a `{` and a later `}` with no empty line between changes its parse |

The last two need no hypothesis.  `AstEq.blocks_eqb` decides the parse
test (`blocks_eqb_eq`).  Brace pairs across an empty line are left out
because a span cannot cross one, and because there are too many: the
rendering of `djotjs-divergences.md` has 694 `{` and 616 `}`.

`shrink` sweeps forward from the last deletion and starts over from the
first byte only when nothing ahead can go, so it stops only when no
deletion of the whole string is accepted (`shrink_final`).

## The end state

One renderer is public: the renderer below.  It carries both
theorems, round trip and irredundancy; irredundancy presupposes the
round trip (no escape can go while the output still parses back), so
it is the stronger of the two.

`Render.render_djot` stays as a step inside its definition: the
renderer shrinks what `render_djot` writes.  Its round trip
is `Roundtrip.roundtrip_blocks` plus the fact that each deletion keeps
the parse, so `Render.v` and `Roundtrip.v` stay, as internal layers
that are not exposed as a renderer.  The facade's djot output
(`Doc.to_string`) and the playground switch to it.

Since the shrink takes out every escape the parse does not need,
`render_djot` only has to round-trip, not to look good.  Now that the
renderer is proved, its relaxations (a delimiter between
spaces left bare, destinations escaping only `\`, `(`, `)` and `` ` ``)
can go back to escaping every punctuation byte of a `Str`, if that
simplifies `InlineView.v` and `InlineInvert.v`.  Measure how much proof
it removes before doing it.

## The renderer

`Irredundant.render_djot_irredundant` is the specification
(`irredundant_is_spec`), so its theorems are the specification's:
`irredundant_roundtrip`, `irredundant_backslash`, `irredundant_braces`.
It runs the same test incrementally.  It keeps the current string's
parse as a trace, the parser state before each line and the blocks
each line commits, and the lines.  A candidate carries the bytes it
deletes, so the changed lines are rebuilt from the cached ones
(`del_lines`) without splitting or comparing the whole string.  A
deletion is tested by reparsing from the first changed line until both
runs are idle on the same remaining lines; from there the two parses agree (`Uniformity.prefix_determinism`),
so the blocks committed until then decide (`fast_test_correct`).  An
accepted deletion's trace is the old one with the reparsed lines
replaced, so nothing is parsed twice.  The proof is about the line fold
only, and says nothing about canonical documents.

Times: the README 0.03 s, `djotjs-divergences.md` (140 KB) 1.3 s,
`syntax-reference-coverage.md` 1.2 s.  A test costs the reparse from its
line to the next idle point, so the cost is linear in the document times
the size of its largest paragraph or table.  The coverage file is one
57 KB table, whose state keeps each row's source, so a deletion in it
reparses to the table's end.  On the 140 KB file about half the time is
outside the tests: each candidate string is built (a copy of the
document), and so is the string after each accepted deletion.  Running
the shrink on the lines throughout would remove that.  Resyncing where two open containers' states are equal,
not only where both are idle, was tried and saved nothing.

A test that parsed each top-level block on its own (phase 3) gave the
same output on every input tried, but its round trip needed a locality
theorem about the parser, and its irredundancy did not follow from it.

## Progress

- 2026-10-15, phase 1.  `RenderScan.render_djot_scan` is
  `Render.render_djot` with the paragraph text spelled by
  `text_lines_scan`; `Render.render_lines_with` takes the text function,
  and `render_lines` is it at `text_lines`, so the block layer is shared.
  The rule differs from the one first planned, which read the scanner's
  state at the byte:
  - A bare byte is tested against the rest of the paragraph spelled with
    every escape, not against the view at that byte: bare iff the text
    then has the reading the fully escaped spelling has.  It covers the cases the local rule
    needed special handling for (`\` before a letter, the byte after a
    run, `[^` and `{%`).
  - The reading is the block parser's on the paragraph's text alone,
    which must be one paragraph.  The inline scan alone missed
    `{_=a_}`, an attribute line.
  - Line starts are escaped as `Render` escapes them.
  - Quadratic in a paragraph's length: a parse per punctuation byte.

  Every round-trip pool passes at the depths the Makefile runs, and so
  does the escape pool.  The 539 left: 234 braced spans, 160 in
  table cells, which still use `Render`'s spelling, 23 in destinations,
  105 at the start of a line after a heading, quote or list prefix or
  on a paragraph's later lines, where nothing opens, and 17
  `<`.  In `a \<b< c` either `<` may be bare,
  but the test sees the escaped one after it inside an autolink
  candidate, which keeps the backslash raw.  So the fully escaped tail
  is not neutral after an opener that reads raw, and the spelling is not
  irredundant even where the rule applies.

## Blank lines inside containers

Carried over from the archived plan; no phase above touches it.

`indent_lines` and `quote_line` prefix blank lines, so the output has
lines holding only spaces, or `> ` with a trailing space.  The fix is to
leave a blank line empty (bare `>` in a quote).

The uniformity proofs are stated over "the prefix on every line"
(`ListUniformity.v`, `OrderedList.v`, `Uniformity.v`, `Roundtrip.v`).
The missing lemma: a blank line steps the same with or without the pad.
That needs an invariant on open code fences, since a fence at a smaller
indent would keep the pad as content.

A post-pass that strips whitespace-only lines is unsound: it also
changes whitespace-only lines inside code blocks.

- 2026-10-24, list items: done.  `indent_line` leaves an empty line
  empty, and `indent_lines` uses it, so the list uniformity theorems
  are stated over that layout.  The lemma was not missing:
  `Step.step_fuel_empty_off` and `step_fuel_shift` give
  `Step.step_empty_pad`, an empty line commutes with a pad, and no
  invariant on code fences is needed, since an item's state is already
  `pad_state` of the state its lines would have at top level.  Only
  the shift lemmas and the line-shape lemma in `Roundtrip.v` changed.
- Left: a quote's blank line (`>` instead of `> `), and a footnote's
  first line on its label's line.

## Costs and risks

- The renderer reparses from each candidate's line to the next idle
  point.  A large table, or any long run that is never idle, makes that
  the rest of the block; the coverage table is the slowest input
  measured.
- Output depends on context.  An edit in one part of a paragraph can add
  or remove an escape elsewhere in it.
- The output depends on the order deletions are tried in: two deletions
  may each be possible but not both.  The theorems hold for any order.
- Every statement is under `Context {T : dtable}` and `{K : bconfig}`,
  so the specification follows the table and the block settings in
  force.
