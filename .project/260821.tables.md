# Plan: pipe tables

Everything in §1 was measured against djot.js (and, where it says so,
djoths).  Nothing here is read off the prose spec.

## 0. Why this one, and what it is not

Tables are the largest construct with a node in `Ast.v` and nothing
producing it: 10 of the 28 remaining corpus cases, and with definition
lists (6) and task lists (3) the whole block-level residue.  Two reasons
beyond the count.

**Cells hold inlines, not blocks.**  `Cell ct al ils`.  Every cell is one
call into the inline layer that just finished, so the part that would
have been stubbed a month ago is now free.  Tables are the construct
that became cheap *because* Phase 3 landed.

**One correction to the pitch.**  The retroactive header rule (a row
becomes a header when the *next* line turns out to be a separator) was
sold as the thing that stress-tests the block state machine.  It is not,
and §2.2 says why: if the state accumulates rows in source order and the
head/align assignment is a fold at close, the rule is a pure function
over a list, and no state ever revises an emission.  This is
[[project-engineering-lessons#Split a fix by proof cost before landing
it, and look for the cheap spelling]] applying before the expensive
spelling was written rather than after.

The genuinely retroactive part is the **caption**, which is a separate
block that reaches backward into a table that has already been emitted,
across any number of blank lines.  It is step 4, priced separately, and
it is the only part of this plan that touches list tightness.

## 1. What the oracle does

### 1.1 Rows

A table row is a line matching `\|[^\n]*\|[ \t]*` (`pattTableRow`,
`block.ts:58`): at least two bars, the last bar optionally followed by
whitespace.  Anything after the last bar that is not whitespace makes
the line not a row (`| a | x` is a paragraph).

Cells are split on unescaped bars outside verbatim
(`parseTableCell`, `block.ts:834`): a `\|` is a literal bar, and a bar
inside a backtick run belongs to the verbatim.  A cell whose verbatim
never closes makes the whole row fail: `` | `a |` `` is a paragraph
(`tables.test:31`).  A failed row **ends the table** and starts a
paragraph; it is not a lazy continuation.

Each cell is inline-parsed by its *own* `InlineParser`, so a delimiter
never crosses a bar: `|a|   *b*|` / `|*c| d* |` gives literal `*c` and
`d*` (`tables.test:13`).

Cell text is trimmed on both sides, with one wrinkle: djot.js strips
trailing spaces only when the cell's last inline event is a `str`
(`block.ts:929-936`).  Measured, that is nearly plain trimming, but
`| a\ |` keeps its escaped space and renders `a&nbsp;`.  A right-trim
that stops at an escaped space matches every case probed; see §5.

A table does not interrupt a paragraph, for the reason nothing in djot
does: `checkStarts` is false whenever the last matched container's
content is `Inline` (`block.ts:1015-1019`).  Confirmed for `#`, `-`,
`---` and `|` alike.  This is exactly our `classify` + `step` shape, so
`KRow` needs no new dispatch rule.

### 1.2 Separators, and the alignment fold

A separator line is a row whose every cell matches `(:?)--*(:?)[ \t]*`
and which ends exactly at end of line (`pattRowSep`, `block.ts:49`, plus
the `p === this.starteol` test).  So:

| line | verdict |
| --- | --- |
| `\|-\|` | separator, one default column |
| `\|--- \|` | separator (trailing space before the bar is in the pattern) |
| `\|---\|   ` | separator (whitespace after the final bar is allowed) |
| `\| --- \|` | **not** a separator: a body row containing an em dash |
| `\|---\|x\|` | not a separator |
| `\|:-\| -: \|` | separator: the leading space is allowed on every cell *but the first* |

The `| --- |` case is a logged disagreement (`oracle-disagreements.md`,
`tables.test:111`): djoths trims cells first and reads a separator.
djot.js is the authority and the corpus pins it.

What a separator does, at `-row` (`parse.ts:987-1014`):

1. it sets the table's current aligns, which apply to every *following*
   row, positionally, defaulting to `default` past the end;
2. if the immediately preceding sibling is a row, that row becomes a
   header and each of its cells takes the corresponding align.

So headers may occur anywhere and any number of times, each governing
the rows after it (`tables.test:47`), a separator with no row before it
just sets aligns (`|--:|` then `| b |` is one right-aligned body row),
and a table of separators alone is a table with **zero rows**
(`<table>\n</table>`, `tables.test:97`).  Both oracles agree on all of
these.

### 1.3 Captions

`^` plus at least one space opens a caption (`pattCaptionStart`).  It is
a *sibling* block whose content is inline and which continues while the
line is non-blank (so it swallows following lines, `| b |` included).
At `-caption` it is merged into the preceding sibling if that sibling is
a table, and otherwise **dropped entirely** (`parse.ts:1048-1069`).

Measured:

- `| a |` / blank / blank / `^ cap` attaches.  Any number of blanks.
- `| a |` / blank / `p` / blank / `^ cap` does not: the caption is
  dropped and produces no output.
- `- x` / blank / `^ cap` produces the list and nothing else.
- `^ cap` before the table swallows the table's line as caption text and
  then, having no table to attach to, **the whole document renders
  empty**.  djoths makes it a paragraph.  New disagreement, not yet
  logged; see §5.
- The reach is sibling-local: `> | a |` / blank / `> ^ cap` is two
  blockquotes and the caption is dropped.

### 1.4 Nesting and attributes

A table inside a quote or a list item works with no special handling
(the container prefix is stripped first), and `{#id}` before a table
attaches as it does to any block.  Nothing here needs a column recorded
in the state: a row's content is what is left of the line after the
prefix, and no part of it is measured against the opener's column.

## 2. The change

### 2.1 The AST, first

`Table (caption : option (list (node block))) (rows : list (list cell))`
is a transcription of djoths (`AST.hs:241`, `newtype Caption = Caption
Blocks`).  djot.js's caption is `ContentType.Inline`, and §1.3 confirms
the content is inline-only.

**Propose:** `Table (caption : option inlines) (rows : list (list cell))`.

The reason to do it now rather than later is `block_ind2`.  `htable` has
no induction hypothesis for the caption's blocks today
(`Ast.v:294`, "must be discharged outright; nothing produces them yet"),
so the first proof that needs to descend into a caption is stuck and the
repair at that point is a change to the induction principle.  With
inlines the constructor is a genuine leaf and stays one.  `wf_block`'s
clause loses `nonempty bs && wf_bs bs` and gains `wf_inlines`.

Cost: one constructor, one `wf_block` clause, one `block_ind2` binder,
nothing else, because nothing produces `Table`.

### 2.2 Row scanning, in `Line.v`

```coq
Inductive trow : Type :=
  | TSep (aligns : list align)
  | TCells (cells : list string).      (* cell source, trimmed *)
```

`table_row : string -> option trow`, separator tried first, exactly as
`parseTableRow` does.  `classify` gains `KRow (r : trow)`, placed with
the other openers; no other construct starts with `|`, so the
fallthrough order is free.  `TCells` carries *source*, not inlines: the
block layer owns line structure and hands each cell to
`parse_inline_line` at close, which is what `CPara` already does per
line.

**Obligation prediction.**  No existing `classify_*` lemma acquires a
hypothesis; each gains one more `discriminate` case, which is
mechanical.  `is_text` and the paragraph-continuation facts need `KRow`
excluded the way `KFoot` and `KRef` are.

### 2.3 The state

```coq
| PTable (rows : list trow)      (* reversed, raw, in source order *)
```

and the head/align assignment is `table_block : list trow -> block`, a
single left fold carrying the current aligns and the previous row's
index.  Nothing revises an emission, so:

- **`step_fuel_shift` / `step_fuel_pad`**: `PTable` records no column, so
  it is the free case, unlike `PAttr`, `PRef`, `PFoot`, `PFence`.  This
  is the check [[project-engineering-lessons#Probe the definitions a
  theorem already constrains, too]] demands, and it passes by
  construction.  Run the two-line `Compute` anyway.
- **`step_blank_finish`**: a blank closes the table (step 4 revisits).
- **`blank_absorbed PTable = false`** in step 3, which is what djot.js
  does: the blank closes the table *and* is recorded for tightness.
- **`finish_wf` / `finish_supported`**: need `wf_block (table_block rs)`,
  i.e. every cell's inlines are `wf_inlines`, which is the same
  obligation `CPara` discharges per line.

A row that fails to scan is a `KText` line arriving at `PTable`, which
closes the table and re-dispatches at idle: the existing
close-and-reopen shape, not a new one.

### 2.4 HTML

`Html.v:279` is a `TODO Phase 1` stub.  `<table>`, optional
`<caption>`, `<tr>`, and `<th>`/`<td>` with
`style="text-align: left;"` and friends for a non-default align.  Leaf
work; the only judgement is the newline layout, which the corpus pins
exactly.

## 3. Steps, in cost order

1. **AST**: caption becomes `option inlines`.  Half an hour, no
   producer to break.
2. **`table_row` + `KRow`** in `Line.v`, with the separator decision of
   §1.2 and `Examples` for every line in the table there.  Self-contained;
   `make probe` reachable.
3. **`PTable` + `table_block` + HTML**, no caption.  Expected to close
   most of `tables.test`; the caption case (`tables.test:38`) and
   anything using one stays out.  Corpus number here, before step 4.
4. **Captions**.  Design: `PTable` does not close on a blank but enters a
   caption-waiting state that (a) still reports `blank_absorbed = false`,
   so list tightness is untouched, and (b) closes on the first non-blank
   line that is not a caption opener, emitting the table and
   re-dispatching.  The two obligations to check *first*, by probe:
   whether the waiting state breaks `step_blank_finish`, and whether
   `- | a |` / blank / `  ^ cap` keeps the tightness djot.js gives it.
   If either bites, land steps 1-3 alone and log the residue with the
   lemma that stopped it.
5. **`Document.v`**: a `Table` arm in whatever the whole-document pass
   walks, so a link or footnote reference inside a cell resolves.  Read
   `doc_pass` before pricing; the comment at `Document.v:246` says this
   is owed.

## 4. The canonical view, deferred on purpose

`cblock` has no footnote-definition constructor either, so a construct
landing in the parser without joining the roundtrip is the established
pattern, not a shortcut.  Recording what a `CTable` would owe, because
it is the interesting part and it should be written down before it is
attempted:

An arbitrary `list (list cell)` is **not renderable**.  Aligns propagate
from the last separator, so two consecutive body rows cannot differ in
alignment: putting a separator between them would turn the first into a
header.  So `cb_ok` for a table is a real condition, roughly "alignment
is constant per column across each run of body rows, and changes only at
a header", plus the ordinary leaf conditions (a cell's source contains
no unescaped `|`, no unclosed verbatim).  A table with zero rows is
representable (`|---|`), which is a pleasant surprise and probably still
worth excluding.

That condition is the content.  It is also the reason not to attempt it
in the same step as the parser: it is a `cb_ok` clause with a
non-obvious shape, and the parser half has a corpus number without it.

## 5. Open questions

- **Trailing-space trimming.**  Is "right-trim unless the whitespace run
  is preceded by an odd number of backslashes" extensionally equal to
  djot.js's "strip only if the last inline event is a `str`"?  Probe
  before choosing; if not, take the cheap rule and log the difference.
- **A caption with no table.**  djot.js swallows following lines and
  then drops everything; djoths makes it a paragraph.  We produce a
  paragraph of the source lines, which is djoths' answer and the one
  `wf_block` can represent: dropping input is not something the roundtrip
  can see, but silently emptying a document is worse than diverging.
  Needs an `oracle-disagreements.md` entry under "ours" before step 4
  lands, with that sentence as the boundary.
- **`| --- |`.**  Already logged; restating it here because step 2 is
  where the decision becomes code, and the decision is djot.js.

## 6. Progress

### Steps 1-3, tables without captions: landed

The AST first: `Table (caption : option inlines) (rows : list (list
cell))`, so the constructor is a leaf for `block_ind2` and `wf_block`
asks `nonempty ils && wf_inlines ils` of a caption that is present.  The
nonemptiness is what the oracle forces: `^ ` with nothing after it opens
a caption with no content, and djot.js renders that as no caption at all,
so `Some []` would be a second spelling of `None`.  The parser will owe
that collapse in step 4.

`Line.table_row` is the recognizer, `trow` its answer, and eighteen
`Example`s pin it -- one per line probed against the oracle, the
separator's spacing rules included.  `classify` gains `KRow`, and with it
one obligation that was not predicted: `classify_ktext` acquired a
`table_row l = None` hypothesis, since KRow now sits between KRef and
KText in the fallthrough.  It has no users outside `Wf.v`'s
`classify_ktext_nonblank`, which discharges it by computation.

`PTable (rows : list trow)` is the state, and it is the free case for
`step_fuel_shift` and `step_fuel_pad` exactly as predicted: it records no
column, so both go through by `reflexivity` on the new branch.
`blank_absorbed` and `lazy_ok` are `false`, `pad_safe` and `blank_safe`
`true` by their defaults, and the continuation rule is `PRef`'s -- a row
line extends the state, anything else emits the table and reprocesses the
line from idle.  `table_fold` does the head/align assignment at close,
and the retroactive half is one line: a separator rewrites the head of
the accumulator.

The renderer needed the footnote path as well as the stateless one.
`render_block_foot` fell through to `render_block` for a table, which
silently dropped a footnote reference in a cell; `render_rows_foot`
threads the counter.

**Measured.**  Corpus **259 -> 268/287**, `--shape` **271 -> 280**.
`tables.test` is 9 of 10, the one left being the caption case
(`tables.test:35`); `tables.test:111` is a gallina *match* and a djoths
mismatch, which is the trimming SPEC-GAP resolved our way.  The generated
corpus and the extracted roundtrip are unchanged at 4044/4080 and
29358/29358, since the enumerator produces no tables.

### Step 4, captions: landed

Both obligations the plan said to probe first came out clean, and for
one reason: a state may consume a line without that line counting as
absorbed.

`blank_absorbed (PTable _ _)` stays **false** while the table stays
**open**, so the blank arms the enclosing list exactly as djot.js's
`blankline` event does, and `- | a |` / blank / `  ^ cap` / blank / `- y`
is loose in both.  `step_blank_finish` survives because `TOpen` and
`TAfterBlank` have the same caption -- `None` -- so the block the table
would emit is the same either way, and the equation closes by
`reflexivity` on both.

`tcap` is the state: `TOpen` (still taking rows), `TAfterBlank` (rows
over, table not), `TCaption ls` (accumulating, reversed, a paragraph
accumulator in all but name).  `TAfterBlank` has to be a state rather
than a flag because a row after a blank starts a *second* table, which
is the one thing the blank does end.

**`^` is not a `line_kind`.**  `Line.caption_open` is consulted by the
table's continuation rule and nowhere else, which makes §5's divergence
structural: there is no caption container to be in the wrong place, so a
caption without a table is a paragraph rather than a block that deletes
itself and everything after it.  It also costs `classify` and `is_text`
nothing, where a `KCaption` would have narrowed `cb_ok` for every
paragraph line beginning `^ `.

**Measured.**  Corpus **268 -> 269/287** and `--shape` **280 -> 281**,
which is `tables.test` complete at 10 of 10.  Generated and roundtrip
unchanged.  Logged in `oracle-disagreements.md` under "ours".

### Step 5: a comment, not a change

`assign_ids` walks blocks looking for headings and a table holds none;
reference resolution in cells already worked, because `render_inlines`
sits inside `Section WithRefs`.  The one real gap was in the *other*
renderer, and it was fixed in step 3: `render_block_foot` fell through
to the stateless path for a table and dropped a footnote reference in a
cell.
