# Plan: state the reference's tightness rule (LS4)

## Goal

A theorem that says when a list is loose, written from the syntax
reference rather than from the parser's scan.  `list_uniformity` gives
the spacing as `list_spacing_of`, which runs `step` over each item's
lines (`lines_loose`, `seps_loosen`): the parser describing itself.

The rule, as adjudicated (entries 2026-09-29 in `djotjs-divergences.md`):
a list is loose exactly when a blank line lies between two of its items,
or between two of one item's own blocks, except

- a blank directly before a nested list inside an item (the reference's
  `- two` / blank / `  - sub`);
- a blank directly after a nested list ends (jgm's `lists.test` 242
  and 308);
- a blank inside a nested block (a div, a code block, a footnote, a
  table before its caption, a nested list's own items), which counts
  only for that block.

A blank after an item's last line lies between items even when the item
leaves a div open: the div ends with the item, before the blank (entry
2026-09-30).  It does not when it becomes a line of an open code block.

The first two are the reference's "blank lines at the start or end of a
list" applied to a nested list.  "Ends" looks through a footnote and a
keyed block to their last block, since those stay open across a blank.

## Statement

In `theories/Tightness.v`.  "Between two blocks" without source
positions, said with parses:

```
starts_block pre b y :=
  parse_lines (pre ++ [b; y]) = parse_lines pre ++ parse_lines [y]

separates L i :=
  is_blank b /\ pre has a nonblank line /\
  ends_list (parse_lines pre) = false /\
  the first nonblank line l of post does not open a list /\
  starts_block pre b l /\
  starts_block pre b (blanks (indent_of l) ++ "x")
  (pre := firstn i L, b := nth i L, post := skipn (S i) L)

separates_after L :=
  parse_lines (L ++ [""]) = parse_lines L /\ ends_list (parse_lines L) = false
```

`starts_block` of the paragraph line catches a blank inside a block
still open that takes the next line: a div, which takes every line, and
a footnote the line is indented into.  `starts_block` of `l` itself
catches a caption after its table.  Both are needed: a paragraph line
is no caption, and `l` alone misses a line that makes no block to count
(a complete attribute spec inside a div parses to nothing either way).

Until 2026-10-05 the two clauses were `closes_at pre` (the paragraph
line at column 0) and the split of the whole item,
`parse_lines L = parse_lines pre ++ parse_lines post`.  The parser
loosens only where those hold, but the converse from the split needs a
proof that two parses of arbitrary remaining lines differ, and for a
footnote or a caption they can agree in every block but one.  The
clauses above look at one line after the blank, where keeping the line
and starting afresh differ by one block.

`separates_after` first used `closes_at` too, which counted a blank
inside a div left open inside a footnote (`- [^1]: :::` / blank / `- b`)
as closing it, since the paragraph line ends the footnote; the list was
tight.  That led to the 2026-09-30 entry, and to the form above.

Proved:

```
item_loose_separates : run_safe L -> is_blank (hd L) = false ->
  item_loose L = true -> exists i, separates L i
separates_item_loose : blank_safe (state after firstn i L) ->
  separates L i -> item_loose L = true
separator_separates : run_safe L -> ends_open_container L = false ->
  separates_after L
list_spacing_separates : list_spacing_of sp itemss = Loose -> a blank
  separates inside some item, or sp = Loose and one separates after
  some item that is not the last
separates_loosens : In L itemss -> blank_safe (state after firstn i L) ->
  separates L i -> list_spacing_of sp itemss = Loose
separates_after_reaches : run_safe L -> separates_after L ->
  ends_open_container L = false
separates_after_loosens : every item run_safe -> separates_after L ->
  list_spacing_of Loose (pre ++ L :: M :: post) = Loose
```

`separates_item_loose` asks that the lines before the blank leave no
code block open (`blank_safe`).  A blank inside an open code block is
the block's text and the parser does not count it; that it fails
`separates` shows only in the code block's text, and with a footnote
around the block no count of blocks tells the two parses apart.  With
keyed blocks on the hypothesis also excludes a key holding a fenced
block: `[^1]: k:` / `  :::` / `  a` / blank / `x` parses to the footnote
and a paragraph, the blank between them, and the parser calls the item
tight because the key holds the blank until the div's closing fence.
